## 1. Правила «Однорукого Глека»

- 3 барабани × 3 рядки, **5 ліній**; ставка ділиться між лініями порівну (ставка на лінію = ставка ÷ 5).
- Лінії (рядок кожного барабана, 0 — верх): 0 — середня `[1,1,1]`, 1 — верхня `[0,0,0]`, 2 — нижня `[2,2,2]`,
  3 — діагональ `[0,1,2]`, 4 — діагональ `[2,1,0]`.
- Платить однаковий ряд **зліва направо від першого барабана**; на лінії — один виграш. **Дядько Глек** — дикий,
  замінює всіх; три Глеки — найбільша виплата.
- **«Глек чхнув» 🤧** (з 09.10, «98 %»): після зупинки барабанів з шансом **1 з 12** Дядько Глек чхає — **1–3 клітинки**
  (лише ті, де не Глек) стають дикими Глеками, і всі лінії рахуються вже на зміненому полі. Скільки клітинок: 1 — 70 %,
  2 — 25 %, 3 — 5 %; які — рівномірно серед не-Глеків. Шанс завжди той самий: не залежить ні від історії, ні від
  балансу, ні від серії програшів (той самий `ISlotRng`, одна перевірка `rng.Next(12) == 11` на оберт).
- Після будь-якого виграшу — **Ворожка**: вгадай колір карти (♥ червона / ♠ чорна) — виграш ×2, до 5 разів поспіль;
  не вгадав — згорів. «Забрати» або новий оберт — Ворожка закрита.
- Кожна ставка кладе 1 % у спільну **Скарбничку Глека**; будь-який оберт може її зірвати (§4).

## 1.2. Правила «Цвіту папороті» (slot-cluster)

- Поле **7×7** у вінку, символи падають згори (сценарій — поле за полем `grid[c][r]`, r=0 — верх).
- **Кластер** — 5 і більше однакових, що стикаються боками (не навскіс). **Листок папороті** (`fern`) — дикий, входить
  у будь-який кластер (і в кілька різних одночасно); самі дикі не платять. Цвіт (`bloom`) — теж дикий.
- **Перелесник** (сюрприз, з 09.10.2026): на початку кожного оберту — і вільного теж — одразу після нового поля, до
  пошуку кластерів, з шансом **1 з 12** вогняний перелесник пролітає полем ламаною від краю до протилежного краю
  (7 клітинок, по одній на колонку чи рядок, щокроку вбік на 0 або ±1) і лишає на своєму шляху **2–4 листки папороті**
  (рівно 2, 3 чи 4 — порівну) на недикі клітинки шляху — будь-які квіти й дорогі символи. Шанс сталий: не залежить від
  історії, балансу, ставки, серії. Кластери шукаються вже на зміненому полі. У вільних — той самий шанс (бонус від цього
  багатший, і це враховано в RTP).
- Виграшні згасають, решта падає, згори нові — **каскад**, доки є кластери.
- Кожен згаслий символ кладе крапельку в **шкалу папороті** (до 52). Рівні — раз за оберт кожен, по черзі, лише коли
  на полі вже нема виграшу: **11 · Світлячки** — 3–6 недиких клітинок стають листками (з 6 випадкових розкладів береться
  найвигідніший, але з шансом 35 % — просто випадковий); **30 · Русалка** — усі квіти одного виду (f1–f4) стають іншим
  видом (з шансом 70 % — найвигідніша з 12 замін, інакше будь-яка); **52 · Цвіт папороті** — дикий цвіт 3×3 посередині,
  кластери з ним платять, далі **вибух 5×5** (згасає, але крапель не дає) і **5 вільних обертів**.
- Вільні: шкала починає з нуля й **не скидається між обертами**, листків падає більше (вага ×2,2); знову дійшла до
  цвіту — **+3 оберти** (разом не більше 15), шкала й рівні — знову з нуля. Увесь бонус — у тому самому оберті.
- Стеля — **5000× ставки** за оберт (разом із бонусом): виграш, що до неї дотягнув, урізається, і оберт на цьому
  закінчується (без подальших каскадів і вільних).

## 3. Протокол

Гра: `GameInfo("slot-glek", "Однорукий Глек", …, Group Solo, 1–1, Start Immediate, Private, Persistent,
Score HigherIsBetter, Client "slot")`. Відкривається як інші соло (`OpenSolo`), стан — за ніком і переживає заходи.

### Дії (`ctx.act`)
| дія | payload | що робить |
|---|---|---|
| `spin` | `{ bet, seq? }` | оберт. `bet` — з `view.bets`, ≤ балансу. `seq` — `last.seq`, який бачив клієнт: якщо оберт уже пішов (сервер має новіший), повтор нічого не робить (подвійний клік, перевідправлення) |
| `gamble` | `{ pick: 'r' \| 'b' }` | хід Ворожки (лише після виграшу, поки `gamble.open`) |
| `collect` | — | закрити Ворожку (гроші вже в гаманці) |

Відмови (тост): «Така ставка не йде: 10, 20, …», «Бракує черепків: у гаманці N, а ставка M», «Автомати на перерві — …»
(`Slots:Enabled=false`), «Ворожка вже пішла — крути далі», «Червона чи чорна?», «Автомати зачинені — каса не відповідає».

### Вид (`view`)
```js
{
  on: true,                 // Slots:Enabled і каса на місці
```

### Сценарій (`last.script`) — форма моку `scriptFor`
```js
{ bet: 50,
  steps: [
    { t: 'spin', stops: [a, b, c], tease: [] | [2] },
    { t: 'morph', cells: [[c, r, 'glek']…], why: 'sneeze' },              // лише якщо Глек чхнув (1–3 клітинки)
    { t: 'win', items: [{ line, cells: [[c, r]…], sym, amount }], amount },   // лише якщо є виграш
    { t: 'jackpot', amount },                                               // лише якщо зірвано Скарбничку
  ],
  win,          // виграш оберту БЕЗ Скарбнички (уже зі стелею) — на нього відкривається Ворожка
  state: {},    // у slot-glek завжди порожній
  glek3,        // три Глеки на лінії (і ті, що з чиху)
  sneeze?,      // скільки клітинок чхнуло (1–3), лише якщо Глек чхнув
  jackpot?,     // сума Скарбнички, якщо зірвано
}
```
`morph` (чих) — між `spin` і `win`: клітинки (`c` — барабан, `r` — рядок, 0 — верх) завжди не-Глеки на полі зупинки,
різні, 1–3 штуки. Поле після `spin` (стрічки за `stops`) + `morph` — рівно те поле, на якому пораховано `items`
(тест `Every_spin_replays_like_the_client_sees_it` програє 3000 обертів як клієнт). Виграшні `cells` можуть показувати
на чхнуті клітинки — там уже Глек.
`tease: [2]` — лише коли на якійсь лінії перші два символи справді сімка/Глек (третій барабан вирішує); рахується на
полі зупинки, до чиху.

### Сценарій «Цвіту папороті» — форма моку `simulate`
```js
{ bet: 50,
  steps: [
    { t: 'spin', grid: [[k×7]×7] },                                   // нове поле (у вільних — теж)
    { t: 'morph', why: 'perelesnyk', cells: [[c,r,'fern']×2–4], path: [[c,r]×7] }, // перелесник (1 з 12 полів), лише одразу після spin
    { t: 'win', items: [{ cells: [[c,r]…], sym, n, amount }], amount, hold: 250 },
    { t: 'cascade', remove: [[c,r]…], grid, n /*ланка каскаду*/, fern /*шкала після*/, from /*до*/, boom?: true },
    { t: 'lvl', n: 1, cells: [[c,r,'fern']…] },                       // світлячки
    { t: 'lvl', n: 2, from: 'f2', to: 'f4', cells: [[c,r,'f4']…] },   // русалка
    { t: 'lvl', n: 3, cells: [[c,r,'bloom']×9] },                     // цвіт; далі win? + cascade{boom}
    { t: 'bonusIn', count: 5, title: 'Цвіт папороті', sub: 'вільних обертів · шкала не скидається' },
    { t: 'fern', to: 0 },                                             // шкала з нуля (і рівні знову доступні)
    { t: 'fs', left }, { t: 'spin', grid }, …,                         // вільний оберт
    { t: 'fs', add: 3 }, { t: 'fern', to: 0 },                        // повторний цвіт у вільних
    { t: 'bonusOut', total, title: 'Цвіт папороті приніс' },
    { t: 'fern', to: 0, end: true },                                  // завжди останній (до jackpot)
    { t: 'jackpot', amount },                                         // лише якщо зірвано Скарбничку
  ],
  win,                 // разом із бонусом, уже зі стелею
  state: {},
  info: { chain, lv: [n1, n2, n3], maxCl, bonus, fsWon?, pere? /*скільки разів пролітав перелесник*/ },
  cap?: true,          // виграш дійшов до стелі 5000× (див. §9)
  jackpot?,
}
```
Тест `Scripts_replay_step_by_step_like_the_client` програє сценарій крок за кроком, як клієнт: кожен `win` — рівно ті
кластери, що є на полі; `cascade` прибирає саме виграшні (з `boom` — ще й 5×5) і кладе незгаслі вниз; `fern` = `from`
+ згаслі (до 52); рівні — по черзі, лише без виграшу на полі й коли шкала дійшла; русалка міняє **всі** квіти виду;
`morph` перелесника — одразу після `spin`, `why: 'perelesnyk'`, `path` — 7 клітинок ламаною від краю до протилежного
краю (щокроку на клітинку вперед, убік на 0/±1), `cells` — 2–4 різні недикі клітинки цього шляху в порядку польоту, усі
`fern`; наступний `win` — рівно кластери поля після `morph` (`info.pere` = кількість таких кроків).

### Ворожка
Після виграшу `gamble = { amount: win, steps: 0, open: true, n: 0 }`. `gamble {pick}`: сервер списує `amount` ставкою,
тягне карту (`RandomNumberGenerator`), вгадав — нараховує 2×, `amount ×2`, `steps+1` (на 5 — `open:false`, ачівка);
ні — `amount: 0`, `open: false`. Кожен хід збільшує `n` — клієнт перевертає карту `card` і показує `ok`, коли `n` новий.
`collect` чи новий `spin` — `gamble: null`.

### Стрічка заносів
`GET /api/slots/feed` → `{ on, jackpot, mustHit?, bets, wins: [{ nick, game, mult, win, jackpot, at }] }`
(`mustHit` — межа «має впасти до»; поля нема, коли межу вимкнено; у виді автомата — `mustHit` або `null`) — «Заноси тижня»:
за 7 днів, спершу зірвані Скарбнички, далі за множником, до 20. Зберігаються заноси ≥ 20× і всі Скарбнички (≤ 500
останніх). Сума Скарбнички в живому часі — **опитуванням раз на 5–10 с** (лише ті, хто дивиться лобі «Азарт» чи
автомат; відповідь з пам'яті), а не подією хабу на кожен оберт усім; гравцеві в автоматі вона й так приходить у виді.

## 4. Скарбничка Глека

- `SlotsBank` (одинак): сума в `IGameStore` (`slots:bank`), переживає перезапуск; старт і після виграшу —
  `Slots:JackpotSeed` (10 000).
- Кожна ставка додає `Slots:JackpotPct` % (1 %). Таємничий шанс оберту `p = внесок ÷ сума` (після внеску) — тоді за
  будь-якої суми оберт у середньому віддає рівно свій внесок; великі ставки — більший шанс.
- Без межі (`JackpotMustHit = 0`) — важкий хвіст: імовірність, що Скарбничка не впаде за k обертів, ≈
  `seed ÷ (seed + k × внесок)`, 1 з 6 доростала б вище 60 тис., середній час до падіння — нескінченний. Тести
  `Jackpot_pays_back_what_was_put_in_on_average` (чесність шансу на сталій сумі) і `Jackpot_money_is_conserved_on_a_long_run`
  лишились для цього режиму.

### «Має впасти до» (`Slots:JackpotMustHit`, типово 100 000)
- Оберт, на якому сума **досягла б межі**, зриває Скарбничку гарантовано — той, хто доклав останній внесок. Виплата —
  рівно межа, надлишок понад неї (частка внеску) переходить у нову суму. До межі діє той самий таємничий шанс
  `p = внесок у суму ÷ сума`.
- **Чому самого шансу мало.** Гроші Скарбнички за цикл: виплачено = старт + усе внесене за цикл. Якщо старт дає дім,
  виплачується завжди більше, ніж внесено, — на старт за кожне падіння, і жодним множником шансу цього не прибрати
  (найменше переплачування — без шансу взагалі, лише межа: 100 000 ÷ 90 000 = +11 %; з шансом p — +43 %).
  Тому, як у справжніх «must-hit-by», **старт оплачують самі внески**: частка `f` кожного внеску йде не в суму, а в
  запас на наступний старт (`Reserve` у сховищі; від'ємний — дім позичив наперед).
- **Розрахунок f.** Шанс `p = Δ ÷ сума` означає, що на кожну крапельку суми Δ падіння стається з імовірністю Δ/x, тож
  ймовірність дожити від старту S до суми x — `S ÷ x`. Значить, падіння до межі M розподілене зі щільністю `S/x²`, а
  межі доживає `S ÷ M` (10 %). Середня виплата: `E = S × (1 + ln(M ÷ S))` = **33 026** при 10 000 / 100 000. За цикл у
  суму внесено `E − S`, а всього внесено `(E − S) ÷ (1 − f)`; запас має покрити старт: `f × усе внесене = S`, звідки
  `f × E = S`, тобто **`f = 1 ÷ (1 + ln(M ÷ S))` = 30,28 %**. Сума росте на 0,70 % ставки замість 1 %, решта 0,30 % —
  у запас; у середньому виплачується рівно внесене (Скарбничка дає рівно `JackpotPct` = 1 % RTP).
- Межа діє, лише коли `JackpotMustHit > JackpotSeed > 0`; інакше — як було (увесь внесок у суму, старт дає дім).
  `f` рахується наживо з конфігу (`SlotsOptions.SeedShare`).
- Тести (`SlotsSimTests`): `Must_hit_limit_drops_the_jackpot_on_the_spin_that_reaches_it` (межа зриває того, хто
  доклав останній внесок; сума після — старт; `Unfeed` відкочує все); `Must_hit_jackpot_pays_back_what_was_put_in_on_a_long_run`
  (S 1000, M 10 000, ставка 500, 3 млн обертів: виплачено **100,31 %** внесеного, 4596 падінь, на межі 9,5 % (теорія
  10 %), середня 3274 (теорія 3303); внесене = виплачене + сума + запас з точністю до черепка);
  `Must_hit_share_follows_the_formula`; `Feed_shows_must_hit_only_when_it_is_on`.
- Зірвав — крок `jackpot` у сценарії (свято робить клієнт), гроші — `slot-jackpot:<id>`, рядок у Балачках від Глека,
  ачівка `slot-jackpot`, і (при `Slots:OnAir`) — подія `slot_jackpot` живої реклами (фраза з `data/liveads/lines.json`,
  проходить ті самі фільтри: відмова від прожарок, ліміт на годину, пауза на нік).
- Заноси ≥ 100× — теж рядок у Балачках (без ефіру).

## 5. Гроші й падіння процесу

Через `IStakes` з ідемпотентними ключами, за зразком `RouletteBook`:
- причини: `slot-bet:<id>`, `slot-win:<id>`, `slot-jackpot:<id>` (підписи в гаманці — «Однорукий Глек — ставка/виграш»,
  «Скарбничка Глека!»);
- ключі: `slot:<кімната>-<епоха>:<seq>:bet|win|jp`, Ворожка — `…:<seq>:g<n>:bet|win`. Епоха — нова на кожне
  відкриття/завантаження стану: після падіння стан може відкотитись до старшого збереження, і без епохи `seq`
  повторив би ключ, який леджер уже вважає «списаним» (оберт задарма).
- Порядок оберту: (1) результат і Скарбничка в пам'яті; (2) виграшний оберт — запис у журнал каси (`slots:bank`)
  синхронно; (3) списати ставку; (4) нарахувати виграш і Скарбничку, прибрати запис. Впало до (3) — списання нема,
  відновлення прибере запис; між (3) і (4) — відновлення на старті (і підмітання раз на 10 с записів старших за 2 хв)
  знайде списання в леджері й нарахує тими самими ключами. Програшний оберт журналу не пише — там лише списання.
- Суму Скарбнички пишемо разом із журналом (лише виграшні оберти), одразу при виграші Скарбнички і раз на 10 с, якщо
  змінилась: падіння губить щонайбільше внески за ці секунди (гроші дому).

### Правила
- 5 барабанів × 3 рядки, **20 ліній** (`SlotHoldMath.PayLines` = `LINES` моку); ставка на лінію = ставка ÷ 20.
- Платить ряд **зліва направо від першого барабана**, 3+ однакових; на лінії — один виграш. **Бунчук** — дикий, на
  першому барабані його нема (тож ряд Бунчуків ×3…×5 недосяжний — як у моку, таблиця лишилась), на третьому — два.
- **Дукати** — номінал у ставках: ×1, ×2, ×3, ×5, ×10, ×25, **Міні** ×20, **Мажор** ×100. Дукат ламає лінію. На
  стрічках — лише ×1, ×2, ×3, ×5 і Міні (20 дукатів на 150 клітинок); ×10, ×25 і Мажор падають у респінах.
- **«Дукатний дощ»** (сюрприз базової гри): після зупинки **в 1 з 16 обертів** на поле падає 1 дукат (70 %), 2 (22 %),
  3 (6 %) або 4 (2 %), у середньому 1,40. Номінал — як у випадкового дуката зі стрічок (вага — скільки таких дукатів на
  п'яти барабанах: ×1 — 5, ×2 — 5, ×3 — 3, ×5 — 5, Міні — 2). Падає **лише на клітинки, що не дукати й не входять у
  жоден виграшний ряд**, кожна вільна — рівноймовірно; вільних менше — падає, скільки влізло. Шанс — один кидок на кожен
  оберт, без пам'яті: не залежить ні від історії, ні від балансу, ні від серії.
- **6+ дукатів на полі (разом із дощем) — «Утримуй і вигравай»** у тому ж оберті: дукати стають у гнізда, 3
  свічки-респіни. На кожному респіні в кожному порожньому гнізді з шансом 5 % щось падає: Булава 4,5 %, Пірнач 4 %, Міні
  3,5 %, Мажор 0,8 %, інакше дукат ×1 (34 %) / ×2 (26 %) / ×3 (16 %) / ×5 (13 %) / ×10 (8 %) / ×25 (3 %). Впало хоч щось —
  свічок знову 3, ні — мінус одна. (Респіни — без змін.)
- Порядок у респіні: поставити все, що впало → кожен **Пірнач** подвоює всі дукати й Булави (Міні/Мажор — ні; сам нічого
  не платить) → кожна **Булава** збирає собі суму всіх інших дукатів і Булав (вони лишаються на місці й теж платять).
- Наприкінці платить кожне гніздо (номінал × ставка). **Повне поле (15 гнізд) — Гетьманський скарб: оберт віддає стелю
  1000× ставки** (лінії + дукати + доплата скрині).
- Очікування (`tease`) — лише чесне і за полем барабанів (дощ іде вже після зупинки): барабан тягнеться, коли на
  попередніх уже **рівно 5** дукатів.

**Чому дощ не падає на виграшні ряди.** Дукат ряду не складає — лише ламає лінію. Тож якщо він падає поза клітинками
виграшних рядів, жодна лінія не міняється: виграш ліній на полі після дощу **рівно той самий**, що на барабанах, і на
екрані все чесно — підсвічені ряди стоять, дукати лягли поруч. Тому сервер рахує лінії **на полі після дощу** (крок
`morph` іде перед `win`), і це те саме число, що й до нього (тест `Rain_lands_only_on_free_cells_and_never_changes_the_lines`).

### Математика
- **Лінії й виграш — точно**: лінії — частоти символів (рядок на барабані не міняє розподілу); виграш (лінії або бонус) —
  перебір усіх 30⁵ = 24,3 млн полів з точною вагою.
- **Бонус з дощем — перебір усіх полів**: для кожного поля — бонус без дощу (6+ на барабанах) і для кожного k = 1…4 —
  дощ на min(k, вільні клітинки) дукатів (`RainCells`). Очікування скрині — **лінійною моделлю**: «Утримуй і вигравай» від
  стартових дукатів залежить лише через їх кількість n (гнізда рівноправні), а сума лінійна за номіналами (кожен
  звичайний стартовий дукат усі Пірначі подвоюють і всі Булави збирають однаково, джекпот лишається собою). Тож
  E[скриня] = A(n)·S + D(n)·J + B(n) + F(n)·стеля (S — сума звичайних стартових, J — джекпотів, F — шанс повного поля).
  A, B, D, F міряє **справжній `SlotHoldMath.Hold`**: той самий шлях (той самий сід) з усіма номіналами ×1 і ×2
  (≈ 1,3 млн шляхів; σ оцінки RTP ≈ 0,07 %). За лінійністю дощ досить врахувати середнім номіналом (2,45 ставки у звичайних
  + 2,0 від Міні на дукат). Модель звірено з прямими прогонами (тест `Hold_model_matches_direct_runs`: 58,78 ± 0,18 проти 58,95).
- Симуляції — тим самим класом, що грає на сервері (`Spin` → `ScriptFor` з дощем і бонусом).

### Сценарій (`last.script`) — форма моку `scriptFor` + дощ
```js
{ bet, win, state: {}, hold: bool, full: bool, rain?: n, capped?: true,
  steps: [
    { t: 'spin', stops: [5], tease: [c…] },                                          // поле барабанів (до дощу)
    { t: 'morph', cells: [[c, r, key, v]…], why: 'rain' },                           // дощ: key — c1/c2/c3/c5/cmini, v — номінал
    { t: 'win', items: [{ line, cells: [[c, r]…], sym, amount }], amount },         // лише якщо лінії платять
    { t: 'holdIn', coins: [[c, r, 'coin'|'mini'|'major', v]…] },                     // 6+ дукатів (разом із дощем)
    { t: 'respin', left, after, land: [[c, r, k, v]…], slow },                       // k: coin/mini/major/mace/pirnach
    { t: 'double', at: [c, r], cells: [[c, r, v]…] },                                // Пірнач, після свого respin
    { t: 'collect', at: [c, r], from: [[c, r, v]…], total },                         // Булава, після double
    { t: 'holdCount', cells: [[c, r, amt, k]…], total },                             // amt у черепках
    { t: 'grand', amount },                                                          // лише повне поле
    { t: 'holdOut', total },                                                         // що віддала скриня
    { t: 'jackpot', amount },                                                        // Скарбничка (база)
  ] }
```
`win` = сума кроку `win` + `holdOut.total` (без Скарбнички). `flags`: `rain`, `hold`, `grand`. `rain` у сценарії —
скільки дукатів упало (лише коли дощ був). Крок дощу — існуючий `morph` кіта: `[c, r, key]` з ключем **стрічки**
(`c1`…`c5`, `cmini`), тож старий клієнт без змін малює справжній дукат з номіналом (`reelsMorph`: символ + `sk-morph` +
звук `coin`, 450 мс); четвертий елемент (номінал) і `why` старий клієнт не читає. `holdIn.coins` — усі дукати поля після
дощу, стовпчик за стовпчиком, згори вниз. Порядок кидків `ISlotRng`: 5 зупинок → «чи дощ» (`NextDouble`, щооберту) →
скільки (`NextDouble`) → для кожного дуката клітинка (`Next(вільних)`) і номінал (`Next(сума ваг)`) → респіни бонусу.

### Розбіжності з моком
1. **Гетьманський скарб.** Мок клав 1000× **зверху** на дукати й лінії (оберт міг дати > 1000×). Сервер: повне поле —
   оберт віддає рівно стелю 1000×; `grand.amount` = 1000× − лінії − `holdCount.total` (доплата до стелі), `holdOut.total`
   = скриня з доплатою. Клієнт програє без змін (підрахунок → свято з меншою сумою → «скриня віддала»), сума сходиться з `win`.
2. **Стеля без повного поля** (у симуляціях не трапилась): `holdOut.total` обрізається до 1000× − лінії, у сценарії —
   `capped: true`; `holdCount` показує повні суми гнізд.
3. Демо-підкрутки моку (`plan`, `saves`, `fill`, `rich`) — лише для показу на стенді, на сервері їх нема. Правило моку
   «особливі не раніше, ніж є що збирати» не потрібне (у бонусі завжди ≥ 6 дукатів).
4. Випадковість — `ISlotRng` (крипто в проді, сід у тестах) замість `Math.random`; порядок кидків — див. вище.
5. **Математика 98 % (10.10.2026)**: стрічки й виплати — нові (вище), «Дукатний дощ» — лише на сервері (мок його не
   має). Респіни, джекпоти, стеля — як у моку.
6. `view.table` для ⓘ: `reels`, `lines`, `pay`, `payUnit: 0.05`, `wild: 'wild'`, `cap: 1000`, `coins` (номінали дукатів),
   `jackpots: { mini: 20, major: 100, grand: 1000 }`, `holdAt: 6`, `candles: 3`, а ще
   `respin: { land: 0.05, mace: 0.045, pirnach: 0.04, mini: 0.035, major: 0.008, coins: { "1": 0.29648, "2": 0.22672,
   "3": 0.13952, "5": 0.11336, "10": 0.06976, "25": 0.02616 } }` (частки від того, що впало; разом 1) і
   `rain: { chance: 0.0625, counts: { "1": 0.7, "2": 0.22, "3": 0.06, "4": 0.02 }, coins: { c1: 5, c2: 5, c3: 3, c5: 5,
   cmini: 2 }, text: "Дукатний дощ: …" }` (`coins` — ваги, `text` — готове правило для ⓘ).

  розійдуться.

  за `win` (або одразу за дощем, коли ліній нема) — гарно б «дощ → дзвін → скриня».

- ⓘ: правило дощу — `table.rain.text` (шанс `chance`, скільки — `counts`), шанси респіну — `table.respin`; рядок «шість

## «Розбиті глеки» (slot-cascade)

Сервер: `SlotCascadeMath` (`src/Hlechyky/Games/Impl/SlotCascadeMath.cs`) + `SlotCascade` (`SlotCascade.cs`, id
`slot-cascade`, `Client: "slot"`). Порт моку `web/games/slots/slot-cascade.js` (`makeScript` / `tumble` / `bonus`):
сценарій тієї самої форми, клієнт програє його без змін. Гроші, Скарбничка, вид, таблиці — база `SlotGame` (як у
slot-glek), Ворожки нема (`Gamble => false`, `gamble` відмовляє «Тут Ворожки нема»).

З 09.10 (контракт `D:/or-wt/_slots98/PLAN.md`): RTP бази **97 %** (разом зі Скарбничкою — 98 %), призи частіші (виграш
35,7 % → 41,2 % обертів, бонус 1 з 176 → 1 з 125), бонус і найбільші виплати скромніші, сюрприз **«Гончар доліпив»**.

### Правила
- Полиця 6×5 без ліній. Платить **8+ однакових будь-де**: ярус 8–9 / 10–11 / 12+.
- Виграшний посуд б'ється, решта в колонці падає донизу, згори — нові (**каскад**), поки є що бити (до 30 каскадів).
- **«Гончар доліпив»**: якщо на першому падінні базового оберту нема жодної вісімки, з шансом **9 %** приходить гончар
  і переліплює кілька клітинок посуду в один символ так, що на полі стає **рівно 8** таких, — і вони платять, далі каскад
  як завжди. Символ — за вагами гончаря (черепки k1…k4 — 80 %): k1 30, k2 26, k3 22, k4 18, миска 10, горщик 7, макітра 4,
  куманець 2, глек 1 (з 120). Переліплюються випадкові клітинки іншого посуду; **горна й писанки гончар не чіпає**
  (бонус і множники — чесно ті, що впали), інші групи від цього лише меншають, тож платить саме доліплена вісімка.
  Шанс не залежить ні від чого (історії, балансу, серії) — лише від того, що перше падіння без виграшу (≈ 64 % обертів),
  тобто гончар — ≈ 5,7 % усіх обертів (1 з 17,5). У вільних обертах гончаря нема.
- **Писанки** ×2, ×3, ×5, ×10, ×25, ×50, ×100 — не платять самі й не б'ються. Коли каскад заспокоївся і в ньому був
  виграш, писанки на полі (і ті, що впали посеред каскаду) складаються, і весь виграш каскаду множиться на суму.
- **Горно** 4+ будь-де (рахується на полі після каскаду): 4 — 3×, 5 — 5×, 6+ — 100× ставки, і **10 вільних обертів**.
- Вільні оберти — інші ваги (частіші писанки). Множник **накопичується на весь бонус**: кожен виграшний каскад із
  писанками додає їхню суму до накопиченого й множиться на все накопичене (каскад без писанок — без множника, як у моку).
  3+ горна у вільному — ще 5 обертів (поки всього менше 50). Увесь бонус рахується в тому ж оберті.
- Стеля — **5000× ставки** за оберт (разом із бонусом). Досягли посеред бонусу — решта вільних не грається.

### Математика
Як підбирали: `SlotCascadeMath.Probe` рахує, скільки разів платила кожна група (символ × ярус) з урахуванням множника, —
RTP лінійний у виплатах, а частоти (виграш, бонус, гончар) від виплат не залежать. Тож спершу ваги (горно, писанки у
вільних) і шанс гончаря — під частоти, потім таблиця й вага писанки у вільних — під 97 % (прогони тимчасовим
інструментом; конструктор `SlotCascadeMath(ваги бази, ваги вільних, шанс гончаря, ваги гончаря)` — саме для цього).
Гончар коштує дорого (його вісімка теж каскадить і множиться писанками), тому дрібні групи подешевшали: частіші, але менші
виграші. Склад RTP: база (каскади разом із гончарем) ≈ 75,1 %, виплата горна ≈ 3,9 %, вільні ≈ 18,1 % (було 73,4 / 2,7 /
18,8 при 95 %).

- «Середній бонус» — увесь оберт, що відкрив бонус (каскад + горно + вільні); «вільні» — лише вільні оберти. Колонка
  «було» для ≥ 10× і σ — 5 млн обертів старої математики тим самим кодом.
- Волатильність висока, але м'якша: σ ≈ 6,7 ставки (було 7,5). Похибка прямої симуляції: на 200 тис. обертів σ
  середнього ≈ 1,5 %, на 5 млн ≈ 0,3 %. Тому в тестах прямий прогін 200 тис. — ±5 % (> 3σ), 5 млн — ±1 % (> 3σ), а
  точність ±2 % і ±0,5 % — **розшарованою оцінкою**: база окремо (бонус не грається, `Probe.SkipBonus`, але вхід і горно
  рахуються) + частота входу × середній бонус з окремого прогону бонусів (`FastBonus`); σ ≈ 0,5 % на 1 млн + 50 тис. і
  ≈ 0,17 % на 10 млн + 500 тис. Частоти: виграш 200 тис. — 40,5…42 % (σ ≈ 0,11 %), бонус 110…142 (σ ≈ 2,5 %), гончар
  5,3…6,2 % обертів, частка гончаря серед мертвих перших падінь — 9 % ± 1 % (σ ≈ 0,25 %). Усі прогони сідовані.
- `Fast` (без сценарію) тягне ті самі числа, що `Spin` (гончар бере rng так само), — тест звіряє виграші оберт в оберт.

### Сценарій (`last.script`) — форма моку `makeScript`
```js
{ bet: 10,
  steps: [
    { t: 'spin', grid: [[k…5]…6], tease: [c…] },             // поле по колонках, r=0 — верх
    { t: 'morph', cells: [[c, r, key]…], why: 'potter' },    // лише гончар: одразу після першого spin бази
    { t: 'win', items: [{ sym, n, cells: [[c,r]…], amount }], amount, hold: 260 },
    { t: 'cascade', remove: [[c,r]…], grid, n },              // grid — поле ПІСЛЯ падіння; n — номер каскаду
    …                                                         // win/cascade до спокою
    { t: 'mult', cells: [[c,r,v]…], from, to, seq, add, fs },  // лише якщо був виграш і є писанки; каскад = seq × to
    { t: 'furn', cells, amount },                             // 4+ горна (виплата горна)
    { t: 'bonusIn', count: 10 },
    { t: 'fs', left }, { t: 'spin', grid, tease }, …win/cascade/mult (fs: true, from — накопичене)…,
    { t: 'furn', cells, amount: 0, fs: true }, { t: 'fs', add: 5 },    // ретригер у вільних
    { t: 'banner', text: 'Стеля 5000×!', sub, ms },           // лише якщо досягли стелі
    { t: 'bonusOut', total, spins, acc },
    { t: 'jackpot', amount },                                 // база SlotGame, якщо зірвано Скарбничку
  ],
  win,              // повний виграш оберту з бонусом (уже зі стелею), без Скарбнички
  state: {},
  meta: { casc, mults: [to], bonus, tease, fsMults, acc, potter?, fsWin?, spins? },   // potter — ключ доліпленого символу
  capped?: true,    // лише якщо досягли стелі
  jackpot?,
}
```
Символи: `k1 k2 k3 k4 bowl pot makitra kumanets glek furnace x2 x3 x5 x10 x25 x50 x100`. Крок `morph` гончаря: у
`cells` — лише клітинки, що змінились (усі одного ключа, впорядковані по колонках), `spin.grid` — поле ДО гончаря, наступний
`win` рахується на полі ПІСЛЯ нього (рівно одна група — доліплена, `n: 8`). Очікування `tease` — як `teaseFor` моку,
рахується на полі `spin` (гончар горен не чіпає): колонки, що падають, коли до бонусу бракує **рівно одного** горна (база —
4; вільні — 3 і лише поки всього менше 50 обертів); з двох одразу на чотири — без очікування. `view.table` = `{ cols, rows,
min: 8, pay: { glek: {12,10,8}, …, furnace: {6,5,4} }, payUnit: 1, mults, free: 10, retrigger: 5, maxFree: 50, cap: 5000,
bonusAt: 4, retriggerAt: 3, potter: { chance: 0.09, size: 8, syms: { k1: 25, k2: 21.7, k3: 18.3, k4: 15, bowl: 8.3,
pot: 5.8, makitra: 3.3, kumanets: 1.7, glek: 0.8 } } }` (`syms` — у відсотках).

### Розбіжності з моком
1. Таблиця й ваги — див. вище (у моку k1 10–11 0,9, k2 8–9 0,5 тощо; горно в базі 2,3; писанки у вільних 1,6 і M_FS
   34/26/20/12/5/2/1). Ваги клієнта на сервері нічого не вирішують — лише мок і початкове поле.
2. «Гончар доліпив» (крок `morph`, `meta.potter`, `table.potter`) — у моку його нема.
3. Стеля 5000× (мок без стелі): `capped: true`, крок `banner` перед `bonusOut` (у базі — останнім), бонус закінчується
   достроково, `bonusOut.total` і `meta.fsWin` обрізані. Суми кроків тоді більші за `win` — за 5 млн обертів стелі не
   досягнуто жодного разу (найбільше 1362×).
4. `meta.fsWin` — обрізаний виграш вільних (у моку — повний; різниця лише на стелі).
5. Крок `jackpot` і поле `jackpot` — від бази `SlotGame` (у моку їх нема).
6. Демо моку (`o.force`, ваги `W_RICH`/`W_LOWS`/`NOPYS`) сервер не знає — демо лишаються клієнтськими.
