## 1. Правила «Однорукого Глека»

- 3 барабани × 3 рядки, **5 ліній**; ставка ділиться між лініями порівну (ставка на лінію = ставка ÷ 5).
- Лінії (рядок кожного барабана, 0 — верх): 0 — середня `[1,1,1]`, 1 — верхня `[0,0,0]`, 2 — нижня `[2,2,2]`,
  3 — діагональ `[0,1,2]`, 4 — діагональ `[2,1,0]`.
- Платить однаковий ряд **зліва направо від першого барабана**; на лінії — один виграш. **Дядько Глек** — дикий,
  замінює всіх; три Глеки — найбільша виплата.
- Після будь-якого виграшу — **Ворожка**: вгадай колір карти (♥ червона / ♠ чорна) — виграш ×2, до 5 разів поспіль;
  не вгадав — згорів. «Забрати» або новий оберт — Ворожка закрита.
- Кожна ставка кладе 1 % у спільну **Скарбничку Глека**; будь-який оберт може її зірвати (§4).

### Стрічки (по 32, дослівно з моку)
вишня 7, груша 6, слива 6, кавун 4, дзвоник 3, підкова 3, сімка 2 (стоять поруч), Глек 1 — на кожному барабані.
Порядок — `SlotGlekMath.Reels` (той самий, що `REELS` у `slot-glek.js`).

## 1.2. Правила «Цвіту папороті» (slot-cluster)

- Поле **7×7** у вінку, символи падають згори (сценарій — поле за полем `grid[c][r]`, r=0 — верх).
- **Кластер** — 5 і більше однакових, що стикаються боками (не навскіс). **Листок папороті** (`fern`) — дикий, входить
  у будь-який кластер (і в кілька різних одночасно); самі дикі не платять. Цвіт (`bloom`) — теж дикий.
- Виграшні згасають, решта падає, згори нові — **каскад**, доки є кластери.
- Кожен згаслий символ кладе крапельку в **шкалу папороті** (до 50). Рівні — раз за оберт кожен, по черзі, лише коли
  на полі вже нема виграшу: **11 · Світлячки** — 3–6 недиких клітинок стають листками (з 6 випадкових розкладів береться
  найвигідніший, але з шансом 35 % — просто випадковий); **30 · Русалка** — усі квіти одного виду (f1–f4) стають іншим
  видом (з шансом 70 % — найвигідніша з 12 замін, інакше будь-яка); **50 · Цвіт папороті** — дикий цвіт 3×3 посередині,
  кластери з ним платять, далі **вибух 5×5** (згасає, але крапель не дає) і **5 вільних обертів**.
- Вільні: шкала починає з нуля й **не скидається між обертами**, листків падає більше (вага ×2,2); знову дійшла до
  цвіту — **+3 оберти** (разом не більше 15), шкала й рівні — знову з нуля. Увесь бонус — у тому самому оберті.
- Стеля — **5000× ставки** за оберт (разом із бонусом): виграш, що до неї дотягнув, урізається, і оберт на цьому
  закінчується (без подальших каскадів і вільних).

## 2. Математика

Точний RTP рахується перебором усіх 32³ = 32 768 зупинок (тест `Exact_rtp_of_one_armed_glek`), симуляції — тим самим
класом, що грає на сервері (`SlotsSimTests`).

| автомат | RTP бази | + Скарбничка | разом | виграш (частота) | найбільший за оберт | стеля |
|---|---|---|---|---|---|---|
| slot-glek, точно | **95,50 %** | 1 % | ≈ 96,5 % | 38,41 % (1 з 2,60) | 122,8× | 1000× |
| slot-glek, 200 тис. обертів | 95,53 % | | | 38,35 % | 122,8× | |
| slot-glek, 5 млн обертів (Perf) | 95,70 % | | | 38,44 % | 122,8× | |
| **slot-cluster**, 56 млн по 100 (оцінка) | **95,2 %** ± 0,1 % | 1 % | ≈ 96,2 % | 40,66 % (1 з 2,46) | 383× | 5000× |
| slot-cluster, 200 тис. (тест) | 92,86 % (−1,5σ) | | | 40,82 % | 244× | |
| slot-cluster, 5 млн (Perf) | 95,66 % | | | 40,67 % | 334× | |

**slot-cluster**: світлячки — 10,24 % обертів (1 з 9,8), русалка — 3,11 % (1 з 32), цвіт папороті й бонус — 1,01 %
(1 з 99); ≥ 10× — 1,06 % обертів (майже всі — бонус), ≥ 50× — 0,44 %, ≥ 100× — 0,13 %. σ оберту — 7,1 ставки
(середня волатильність: виграш у 40 % обертів, але половину RTP дає бонус). Через таке σ стандартна похибка RTP на 200 тис.
обертів — 1,6 %, на 5 млн — 0,32 %: тест на 200 тис. перевіряє ±3 % (2σ; контрактні ±2 % — це лише 1,3σ, і для
сідів 1 і 2 це був би лотерейний тест), Perf на 5 млн — ±0,5 % від оцінки з 56 млн обертів. RTP від ставки: 10 — ≈ 96,2 %
(округлення 2,5 → 3), 20 — 95,5 %, 100 — 95,2 %. Симуляції — той самий клас, що грає на сервері (`Play` без сценарію;
перевірено, що `Play` і `Spin` з одним сідом дають той самий виграш), кусками по 8 сідів паралельно.

- Бонусу (вільних обертів) у slot-glek нема — частота бонусу 0.
- Волатильність низька: 17,8 % обертів — дві вишні (0,2× ставки), 61,6 % — без виграшу; ≥ 10× — ≈ 1,6 %,
  ≥ 50× — 0,04 %, три Глеки на лінії — ≥ 120×.
- Стеля 1000× ставки за оберт: для цих стрічок недосяжна (один Глек на барабані), але в коді обрізається.
- Ворожка — чесні 50/50 і ×2: на RTP не впливає (математичне сподівання ходу — нуль).
- Округлення: виграш лінії — `round(множник × ставка ÷ 5)` (як `Math.round` у моку); для ставок, кратних 5, — рівно.

## 3. Протокол

Гра: `GameInfo("slot-glek", "Однорукий Глек", …, Group Solo, 1–1, Start Immediate, Private, Persistent,
Score HigherIsBetter, Client "slot")`. Відкривається як інші соло (`OpenSolo`), стан — за ніком і переживає заходи.

### Дії (`ctx.act`)
| дія | payload | що робить |
|---|---|---|
| `spin` | `{ bet, seq? }` | оберт. `bet` — з `view.bets`, ≤ балансу. `seq` — `last.seq`, який бачив клієнт: якщо оберт уже пішов (сервер має новіший), повтор нічого не робить (подвійний клік, перевідправлення) |
| `gamble` | `{ pick: 'r' \| 'b' }` | хід Ворожки (лише після виграшу, поки `gamble.open`) |
| `collect` | — | закрити Ворожку (гроші вже в гаманці) |

Відмови (тост): «Така ставка не йде: 10, 20, …», «Бракує черепків: у гаманці N, а ставка M», «Автомати на перерві — …»
(`Slots:Enabled=false`), «Ворожка вже пішла — крути далі», «Червона чи чорна?», «Автомати зачинені — каса не відповідає».

```js
{ bet: 50,
  steps: [
    { t: 'spin', stops: [a, b, c], tease: [] | [2] },
    { t: 'win', items: [{ line, cells: [[c, r]…], sym, amount }], amount },   // лише якщо є виграш
    { t: 'jackpot', amount },                                               // лише якщо зірвано Скарбничку

  state: {},    // у slot-glek завжди порожній
```

`tease: [2]` — лише коли на якійсь лінії перші два символи справді сімка/Глек (третій барабан вирішує).

### Сценарій «Цвіту папороті» — форма моку `simulate`
```js
{ bet: 50,
  steps: [
    { t: 'spin', grid: [[k×7]×7] },                                   // нове поле (у вільних — теж)
    { t: 'win', items: [{ cells: [[c,r]…], sym, n, amount }], amount, hold: 250 },
    { t: 'cascade', remove: [[c,r]…], grid, n /*ланка каскаду*/, fern /*шкала після*/, from /*до*/, boom?: true },
    { t: 'lvl', n: 1, cells: [[c,r,'fern']…] },                       // світлячки
    { t: 'lvl', n: 2, from: 'f2', to: 'f4', cells: [[c,r,'f4']…] },   // русалка
    { t: 'lvl', n: 3, cells: [[c,r,'bloom']×9] },                     // цвіт; далі win? + cascade{boom}
    { t: 'bonusIn', count: 5, title: 'Цвіт папороті', sub: 'вільних обертів · шкала не скидається' },
    { t: 'fern', to: 0 },                                             // шкала з нуля (і рівні знову доступні)
    { t: 'fs', left }, { t: 'spin', grid }, …,                         // вільний оберт
    { t: 'fs', add: 3 }, { t: 'fern', to: 0 },                        // повторний цвіт у вільних
    { t: 'bonusOut', total, title: 'Цвіт папороті приніс' },
    { t: 'fern', to: 0, end: true },                                  // завжди останній (до jackpot)
    { t: 'jackpot', amount },                                         // лише якщо зірвано Скарбничку
  ],
  win,                 // разом із бонусом, уже зі стелею
  state: {},
  info: { chain, lv: [n1, n2, n3], maxCl, bonus, fsWon? },
  cap?: true,          // виграш дійшов до стелі 5000× (див. §9)
  jackpot?,
}
```
Тест `Scripts_replay_step_by_step_like_the_client` програє сценарій крок за кроком, як клієнт: кожен `win` — рівно ті
кластери, що є на полі; `cascade` прибирає саме виграшні (з `boom` — ще й 5×5) і кладе незгаслі вниз; `fern` = `from`
+ згаслі (до 50); рівні — по черзі, лише без виграшу на полі й коли шкала дійшла; русалка міняє **всі** квіти виду.

### Ворожка
Після виграшу `gamble = { amount: win, steps: 0, open: true, n: 0 }`. `gamble {pick}`: сервер списує `amount` ставкою,
тягне карту (`RandomNumberGenerator`), вгадав — нараховує 2×, `amount ×2`, `steps+1` (на 5 — `open:false`, ачівка);
ні — `amount: 0`, `open: false`. Кожен хід збільшує `n` — клієнт перевертає карту `card` і показує `ok`, коли `n` новий.
`collect` чи новий `spin` — `gamble: null`.

### Стрічка заносів
`GET /api/slots/feed` → `{ on, jackpot, mustHit?, bets, wins: [{ nick, game, mult, win, jackpot, at }] }`
(`mustHit` — межа «має впасти до»; поля нема, коли межу вимкнено; у виді автомата — `mustHit` або `null`) — «Заноси тижня»:
за 7 днів, спершу зірвані Скарбнички, далі за множником, до 20. Зберігаються заноси ≥ 20× і всі Скарбнички (≤ 500
останніх). Сума Скарбнички в живому часі — **опитуванням раз на 5–10 с** (лише ті, хто дивиться лобі «Азарт» чи
автомат; відповідь з пам'яті), а не подією хабу на кожен оберт усім; гравцеві в автоматі вона й так приходить у виді.

## 4. Скарбничка Глека

- `SlotsBank` (одинак): сума в `IGameStore` (`slots:bank`), переживає перезапуск; старт і після виграшу —
  `Slots:JackpotSeed` (10 000).
- Кожна ставка додає `Slots:JackpotPct` % (1 %). Таємничий шанс оберту `p = внесок ÷ сума` (після внеску) — тоді за
  будь-якої суми оберт у середньому віддає рівно свій внесок; великі ставки — більший шанс.
- Без межі (`JackpotMustHit = 0`) — важкий хвіст: імовірність, що Скарбничка не впаде за k обертів, ≈
  `seed ÷ (seed + k × внесок)`, 1 з 6 доростала б вище 60 тис., середній час до падіння — нескінченний. Тести
  `Jackpot_pays_back_what_was_put_in_on_average` (чесність шансу на сталій сумі) і `Jackpot_money_is_conserved_on_a_long_run`
  лишились для цього режиму.

### «Має впасти до» (`Slots:JackpotMustHit`, типово 100 000)
- Оберт, на якому сума **досягла б межі**, зриває Скарбничку гарантовано — той, хто доклав останній внесок. Виплата —
  рівно межа, надлишок понад неї (частка внеску) переходить у нову суму. До межі діє той самий таємничий шанс
  `p = внесок у суму ÷ сума`.
- **Чому самого шансу мало.** Гроші Скарбнички за цикл: виплачено = старт + усе внесене за цикл. Якщо старт дає дім,
  виплачується завжди більше, ніж внесено, — на старт за кожне падіння, і жодним множником шансу цього не прибрати
  (найменше переплачування — без шансу взагалі, лише межа: 100 000 ÷ 90 000 = +11 %; з шансом p — +43 %).
  Тому, як у справжніх «must-hit-by», **старт оплачують самі внески**: частка `f` кожного внеску йде не в суму, а в
  запас на наступний старт (`Reserve` у сховищі; від'ємний — дім позичив наперед).
- **Розрахунок f.** Шанс `p = Δ ÷ сума` означає, що на кожну крапельку суми Δ падіння стається з імовірністю Δ/x, тож
  ймовірність дожити від старту S до суми x — `S ÷ x`. Значить, падіння до межі M розподілене зі щільністю `S/x²`, а
  межі доживає `S ÷ M` (10 %). Середня виплата: `E = S × (1 + ln(M ÷ S))` = **33 026** при 10 000 / 100 000. За цикл у
  суму внесено `E − S`, а всього внесено `(E − S) ÷ (1 − f)`; запас має покрити старт: `f × усе внесене = S`, звідки
  `f × E = S`, тобто **`f = 1 ÷ (1 + ln(M ÷ S))` = 30,28 %**. Сума росте на 0,70 % ставки замість 1 %, решта 0,30 % —
  у запас; у середньому виплачується рівно внесене (Скарбничка дає рівно `JackpotPct` = 1 % RTP).
- Межа діє, лише коли `JackpotMustHit > JackpotSeed > 0`; інакше — як було (увесь внесок у суму, старт дає дім).
  `f` рахується наживо з конфігу (`SlotsOptions.SeedShare`).
- Тести (`SlotsSimTests`): `Must_hit_limit_drops_the_jackpot_on_the_spin_that_reaches_it` (межа зриває того, хто
  доклав останній внесок; сума після — старт; `Unfeed` відкочує все); `Must_hit_jackpot_pays_back_what_was_put_in_on_a_long_run`
  (S 1000, M 10 000, ставка 500, 3 млн обертів: виплачено **100,31 %** внесеного, 4596 падінь, на межі 9,5 % (теорія
  10 %), середня 3274 (теорія 3303); внесене = виплачене + сума + запас з точністю до черепка);
  `Must_hit_share_follows_the_formula`; `Feed_shows_must_hit_only_when_it_is_on`.
- Зірвав — крок `jackpot` у сценарії (свято робить клієнт), гроші — `slot-jackpot:<id>`, рядок у Балачках від Глека,
  ачівка `slot-jackpot`, і (при `Slots:OnAir`) — подія `slot_jackpot` живої реклами (фраза з `data/liveads/lines.json`,
  проходить ті самі фільтри: відмова від прожарок, ліміт на годину, пауза на нік).
- Заноси ≥ 100× — теж рядок у Балачках (без ефіру).

## 5. Гроші й падіння процесу

Через `IStakes` з ідемпотентними ключами, за зразком `RouletteBook`:
- причини: `slot-bet:<id>`, `slot-win:<id>`, `slot-jackpot:<id>` (підписи в гаманці — «Однорукий Глек — ставка/виграш»,
  «Скарбничка Глека!»);
- ключі: `slot:<кімната>-<епоха>:<seq>:bet|win|jp`, Ворожка — `…:<seq>:g<n>:bet|win`. Епоха — нова на кожне
  відкриття/завантаження стану: після падіння стан може відкотитись до старшого збереження, і без епохи `seq`
  повторив би ключ, який леджер уже вважає «списаним» (оберт задарма).
- Порядок оберту: (1) результат і Скарбничка в пам'яті; (2) виграшний оберт — запис у журнал каси (`slots:bank`)
  синхронно; (3) списати ставку; (4) нарахувати виграш і Скарбничку, прибрати запис. Впало до (3) — списання нема,
  відновлення прибере запис; між (3) і (4) — відновлення на старті (і підмітання раз на 10 с записів старших за 2 хв)
  знайде списання в леджері й нарахує тими самими ключами. Програшний оберт журналу не пише — там лише списання.
- Суму Скарбнички пишемо разом із журналом (лише виграшні оберти), одразу при виграші Скарбнички і раз на 10 с, якщо
  змінилась: падіння губить щонайбільше внески за ці секунди (гроші дому).

## 6. Конфіг (наживо)
```json
"Slots": { "Enabled": true, "Bets": [10,20,50,100,200,500], "MaxBet": 0, "JackpotPct": 1, "JackpotSeed": 10000, "JackpotMustHit": 100000, "OnAir": true }
```

## 9. Що потрібно від клієнта (`web/games/slot.js`)
1. `api.spin(bet, state, ctx)`: `ctx.act('spin', { bet, seq: view.last?.seq ?? 0 })`, дочекатися виду з новим
   `last.seq` і повернути `last.script`. При першому `update` старий `last` не програвати (лише поставити поле `set`).
2. Баланс — з `view.balance` / події гаманця, а не локальний облік кіта (кіт знімає ставку й додає `win` сам —
   звірити з сервером після сценарію).
3. Таблиця виплат змінилась (§1): `PAY` у `slot-glek.js` оновити або брати з `view.table.pay`.
4. Крок `jackpot` `{ amount }` — свій тип кроку (свято + `addBalance(amount)`): `win` Скарбнички не містить.
5. Ворожка: замість `Math.random` — `ctx.act('gamble', { pick })`, карта/результат/сума — з `view.gamble` (`card`, `ok`,
   `amount`, `steps`, `open`, `hist`, новий хід — новий `n`); «забрати» — `ctx.act('collect')`. Локально не списувати
   й не нараховувати (`addBalance(-stake0)` у моку) — гроші вже рухає сервер.
6. Прапорець демо `script.gamble` сервер не ставить.
7. Лобі: `/api/me` → `slots`; тікер Скарбнички й «Заноси тижня» — опитувати `/api/slots/feed` раз на 5–10 с.
8. **slot-cluster** (`web/games/slots/slot-cluster.js`) програє серверний сценарій без змін — кроки й поля ті самі
   (`spin/win/cascade/lvl/fern/bonusIn/fs/bonusOut`, `info`). Розбіжності з моком:
   - **Стеля 5000×** (мок без стелі): виграш, що дотягнув, урізається — `amount` останнього `win` менший за суму його
     `items`, далі лише `bonusOut` (якщо в бонусі) і `fern {end}`, у сценарії `cap: true`. Клієнту варто показати
     «Найбільший можливий виграш» (зараз просто закінчить). На цих вагах практично недосяжна (найбільше за 56 млн — 383×).
   - Крок `jackpot { amount }` після останнього `fern` і `script.jackpot` — як у slot-glek (п. 4).
   - Світлячки беруть випадкові клітинки частковим Фішером — Єйтсом (той самий рівномірний вибір, що `shuffle().slice`),
     кількість — `rng.Next(4)`; порядок викликів генератора інший, тож той самий сід у моку й на сервері дає різне.
   - `state` завжди `{}` (шкала живе лише в межах оберту — як у моку).
   - Демо-сценарії моку (`demo`, ваги RICH/HOT) лишаються на стенді; сервер крутить лише справжні ваги.
   - `view.table` для slot-cluster — `{ cols, rows, min, sizes, pay: { sym: { "5": …, "16": … } }, weights, fsFern, levels, fs, cap }`.
   - Вид має `mustHit` (межа Скарбнички) — для тікера «має впасти до 100 000».
