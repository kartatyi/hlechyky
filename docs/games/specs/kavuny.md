# Кавуни на ярмарку — соло-crash з ножем (`kavuny`)

Ідея — Вова, записка #38 (Crash Fruit). Дядько Глек на ярмарку в Глечиках підкидає з воза сливи, буряки, яблука, груші,
дині, гарбузи й кавуни, а ти ріжеш їх серпом: кожен розрізаний додає свій приріст до множника, що починається з ×1,00.
Гнилий гарбуз (темний, з мухами) — кінець: усе зібране пропало. «Забрати» — будь-коли до нього.

Сервер: `src/Hlechyky/Games/Impl/Kavuny.cs` (гра), `KavunyCore.cs` (математика, seed → послідовність), `KavunyBook.cs`
(каса, налаштування, підключення). Клієнт: `web/games/kavuny.js` + `kavuny.css`. Тести:
`tests/Hlechyky.Tests/Games/KavunyCoreTests.cs` (математика й симуляція), `KavunyTests.cs` (гра, гроші, античит).

## 2. Правила

1. **Ставка** з гаманця черепків: `Kavuny:MinBet … Kavuny:MaxBet` (типово 10 … 2000; `MaxBet: 0` — без стелі). За
   бажанням — **автозабір** «на ×X» (×1,01 … стеля) і **🔪 авторізання**. «Поїхали!» — сервер списує ставку (§4) і бере
   seed, hash якого людина вже бачила (§3.3).
2. Через 1,2 с (Глек замахується) з воза летять овочі **кидками**: раз на 0,85 с, у кидку 1–4 овочі (§3.2). Кожен летить
   дугою 2,4 с — знизу вгору й назад.
3. **Розрізав** (розчерк мишкою, свайп пальцем, тап по овочу, Ⓐ на паді) — множник `M += приріст`. Приріст вилітає з
   розрізаного («×1,04» = +0,04), вид овоча його й так каже (§3.1). **Не встиг** — овоч падає: нічого не додає й нічого не забирає.
4. **Гнилий гарбуз** не ріжеться. Мить, коли він вилітає, — кінець раунду: «Забрати» гасне одразу (інакше кожен забирав
   би, побачивши гнилого), овоч долітає для краси, Глек регоче. Ставку втрачено.
5. **«Забрати»** — будь-коли після першого розрізу й до гнилого: виграш = ⌊ставка × min(M, стеля)⌋. До першого розрізу
   M = ×1,00 — забрати не можна (інакше це безризикове «поверни ставку»).
6. **Автозабір**: щойно M ≥ X — сервер забирає сам, за фактичним M (крок дискретний, тож може бути трохи понад X).
   Змінити X чи вимкнути — і посеред раунду; поставив нижче за поточний M — забирає одразу.
7. **Авторізання**: сервер ріже кожен овоч через 0,1 с після вильоту (раніше, ніж вилетить наступний). Увімкнув посеред
   раунду — одразу ріже все, що в повітрі, далі — кожен новий. Тоді гра — чистий crash: M дорівнює множнику «ідеального
   різника».
8. **Віз порожній**: множник «ідеального різника» сягнув **стелі** (`Kavuny:MaxX`, типово ×100) — Глек більше не кидає;
   за 3,1 с після останнього кидка раунд платить сам ⌊ставка × min(M, стеля)⌋.
9. `Kavuny:Enabled = false` (наживо): нового раунду не почати («Ярмарок зачинено…»), `on: false` у виді, плитки в лобі нема
   (`/api/me` → `kavuny`); раунд, що йде, догравається й розраховується.

## 3. Математика

### 3.1 Таблиця (перший ярус)

| Код | Овоч | Приріст | На овочі | Вага (з 1000) | Шанс |
|---|---|---|---|---|---|
| `s` | слива | +0,02 | ×1,02 | 230 | 23 % |
| `b` | буряк | +0,03 | ×1,03 | 170 | 17 % |
| `a` | яблуко | +0,04 | ×1,04 | 200 | 20 % |
| `g` | груша | +0,05 | ×1,05 | 150 | 15 % |
| `d` | диня | +0,08 | ×1,08 | 110 | 11 % |
| `p` | гарбуз | +0,15 | ×1,15 | 80 | 8 % |
| `k` | кавун (золотистий блиск) | +0,25 | ×1,25 | 50 | 5 % |
| `K` | **Глеків кавун** (подія) | +1,00 | ×2 | 10 | 1 % |
| `x` | гнилий гарбуз | ×0 — кінець | | — | §3.3 |

Середній приріст — S/Q = 6850/1000 = 0,0685: ×2 — це ≈ 15 розрізаних (як у Вови: «12–15 фруктів»).

### 3.2 Яруси й кидки: ярмарок розгулюється

P — множник «ідеального різника» (того, хто ріже все) перед овочем. Що вищий P, то більші овочі й густіші кидки — інакше
до ×100 треба було б різати чверть години:

| Ярус | P | Прирости × | Овочів у кидку |
|---|---|---|---|
| 0 | < ×3 | 1 | 1, 1, 2, 1, 1, 2… (кидок w: 2, якщо w mod 3 = 2) |
| 1 | ×3 … ×10 | 2 | 2 |
| 2 | ×10 … ×30 | 5 | 3 |
| 3 | ≥ ×30 | 10 | 4 |

Розклад (мс від `t0` = старт + 1200): кидок w — у `w · 850`, овоч j кидка — ще `+ j · 150`. Розмір кидка — за ярусом P на
першому овочі кидка. Політ — 2400 мс.

### 3.3 Чесно наперед: seed → послідовність

1. На старті прилавка (і після кожного раунду) сервер бере **наступний** `seed` — 32 випадкові байти
   (`RandomNumberGenerator`), 64 hex малими — і показує `hash = sha256(seed)` (UTF-8 рядка, hex малими). Людина бачить
   hash **до** ставки; «Поїхали!» грає саме цей seed. Після раунду seed відкривається (`last.seed`), а для наступного
   береться новий. Новий seed — і на кожне відновлення стану (Load): старий міг засвітитись.
2. Овоч №k (k = 1, 2, …): `h = sha256("{seed}:{k}")`, hex. `roll` = h[0..8], `kind` = h[8..16], `edge` = h[16..24] (32-бітні
   беззнакові), геометрія — байти 12..15. F — множник ярусу P (§3.2).
3. **Гнилий**, якщо `(k = 1 і edge·100 < 3·2³²)` або `roll·(1000·P + F·6850) ≥ P·1000·2³²`. Інакше вид — за вагами з
   `⌊kind·1000 / 2³²⌋`, приріст `F·inc`, `P += F·inc`.
4. Кінець — гнилий або `P ≥ стеля` (віз порожній; стеля — у виді, `last.cap`). Запобіжник — 5000 овочів.

```js
// «ⓘ Перевірити» (web/games/kavuny.js): cap — у сотих (×100 → 10000)
async function kavunyCheck(seed, hash, cap) {
  const enc = new TextEncoder();
  const sha = async (s) => [...new Uint8Array(await crypto.subtle.digest('SHA-256', enc.encode(s)))]
    .map((b) => b.toString(16).padStart(2, '0')).join('');
  const W = [230, 170, 200, 150, 110, 80, 50, 10], I = [2, 3, 4, 5, 8, 15, 25, 100], C = 'sbagdpkK';
  const T32 = 1n << 32n;
  let p = 100, codes = '';
  for (let k = 1; k <= 5000; k++) {
    const h = await sha(seed + ':' + k);
    const roll = BigInt('0x' + h.slice(0, 8)), kind = BigInt('0x' + h.slice(8, 16)), edge = BigInt('0x' + h.slice(16, 24));
    const f = p < 300 ? 1 : p < 1000 ? 2 : p < 3000 ? 5 : 10, P = BigInt(p);
    if ((k === 1 && edge * 100n < 3n * T32) || roll * (1000n * P + BigInt(f * 6850)) >= P * 1000n * T32) { codes += 'x'; break; }
    let pick = Number((kind * 1000n) >> 32n), i = 0;
    while (i < 7 && pick >= W[i]) pick -= W[i++];
    codes += C[i]; p += f * I[i];
    if (p >= cap) break;
  }
  return { ok: (await sha(seed)) === hash, codes, potential: p };
}
```

### 3.4 Чому рівно 97 % — і симуляція

Шанс пережити овоч `1000·P / (1000·P + F·6850)`, а середній P після нього — `P + F·6,85`. Добуток — рівно P: множник
«ідеального різника», доки не гнилий, — **мартингал**. Тож хоч яке правило «коли забрати» (на ×X, після n овочів, «коли
страшно»), повертає воно стільки, скільки на початку: ×1 · 0,97 (3 % забирає перший овоч окремим `edge`). Людина,
що пропускає овочі, має M ≤ P на тому ж правилі — отже, ≤ 97 %. Стеля лише зрізає: що понад неї — не платиться.

Точно (динамікою по сотих, `KavunyCoreTests.Exact`) і **симуляцією 10 000 000 раундів** ідеальної гри (той самий `Step`,
що й на сервері; кидки — SplitMix64 замість sha256), стеля ×100:

|---|---|---|---|---|
| ×1,01 | 97,000 % | 96,989 % | 93,31 % | 90,78 % |
| ×1,10 | 97,000 % | 96,967 % | 94,59 % | 82,33 % |
| ×1,20 | 97,000 % | 96,972 % | 94,80 % | 75,20 % |
| ×1,50 | 97,000 % | 96,994 % | 95,28 % | 59,88 % |
| ×2 | 97,000 % | 96,980 % | 95,59 % | 45,66 % |
| ×3 | 97,000 % | 96,985 % | 96,05 % | 31,09 % |
| ×5 | 97,000 % | 96,913 % | 96,19 % | 18,47 % |
| ×10 | 97,000 % | 96,876 % | 96,51 % | 9,47 % |
| ×20 | 97,000 % | 96,892 % | 96,69 % | 4,71 % |
| ×50 | 97,000 % | 96,894 % | 96,81 % | 1,89 % |
| ×100 (стеля = «ніколи не забирав») | 95,836 % | 95,922 % | 95,92 % | 0,96 % |

Скільки цілих овочів вилітає до кінця (гнилий чи стеля), ідеальний різник: гнилий першим — **9,23 %**, 1–4 — 18,7 %,
5–9 — 14,9 %, 10–19 — 17,2 %, 20–49 — 23,5 %, 50–99 — 10,6 %, 100–199 — 4,5 %, 200+ — 1,2 %. Середнє — 27,8, найдовша
послідовність — 328 овочів (≈ 2 хв), найбільший множник «ідеального різника» — ×109,99 (стеля ×100 + останній приріст;
платиться ×100). Віз порожніє в 0,96 % раундів. Глеків кавун — 0,28 на раунд. Округлення черепків донизу з'їдає ще трохи
(ставка 10 на ×1,04 — 10 🏺): чим більша ставка, тим ближче до 97 %.

## 4. Гроші й перезапуск

Каса `KavunyBook` (за зразком `LelkaBook`/`RouletteBook`): дім платить зі своєї кишені. Ключі леджера —
`kavuny-bet|win|back:{кімната}:{epoch}:{раунд}:{nick_key}`; підписи в гаманці: «Кавуни — ставка / забрав / ставку повернуто».

- **Старт** — синхронно під замком кімнати (як ставка рулетки сам на сам): запис раунду в сховище (`kavuny:pending`:
  стіл, раунд, нік, ставка, seed, мить, `Return: null`), тоді `TrySpend`. Не записалось — «Каса зачинена»; не списалось —
  запис прибрано, «Бракує черепків».
- **Кінець** (забрав, гнилий, віз порожній; з дії чи з тіка) — у черзі каси, поза замком: підсумок (`Return`) спершу в
  запис, тоді `Grant` виграшу за ключем `kavuny-win` (гнилий — нічого), запис геть. Стан гри теж іде в сховище з черги
  (`Keep`): раунд, що скінчився на тіку, не лишиться «живим» у `game_state`.
- **Сирота** (раунд, якого не довела кімната): каса на старті процесу (`RecoverAtStart`) і раз на хвилину (запис старший за
  30 хв і жодна жива кімната його не тримає) розраховує за записом: підсумок є — за ним; нема — **раунд анульовано,
  ставку повернуто** (`kavuny-back`). Платить лише тому, чиє списання є в леджері.
- **Load** (відновлення після прибирання кімнати чи перезапуску) зі станом «раунд іде»: запис у касі ще є — просимо касу
  розрахувати його (підсумок із запису, або повернення ставки), людині — `note`; запису нема — раунд уже розраховано,
  лише закриваємо. «Ще раз» після того, як людина встала посеред раунду, — те саме.
- Новий `epoch` на кожен `Start()` і `Load()` — ключ леджера ніколи не повториться.

Вікна, яких не закрито (як у Лелеки): процес упав між «забрав» і чергою каси — підсумку в записі ще нема, тож каса поверне
ставку замість виграшу; між гнилим і чергою — поверне ставку замість програшу. Деплой посеред раунду — так само
«анульовано». Перезапуск людина викликати не може, тож на цьому не заробити.

## 5. Античит: розріз — лише поки овоч у повітрі

- Клієнт **не знає майбутнього**: у виді лише овочі, що вже вилетіли (`at ≤ t`), seed — лише після раунду, ні довжини,
  ні наступного виду. Розклад кидків передбачуваний, вміст — ні.
- Розріз — реалтайм-ввід `input('cut', { ids: [3, 4] })` (квота каркаса 30/с, до 64 номерів за раз). `t` — мить, коли
  **сервер отримав** намір (мс від `t0`), час клієнта не береться. Овоч k ріжеться, якщо:
  `at_k ≤ t ≤ at_k + 2400 + 700`, `t < кінець раунду`, k не гнилий, ще не розрізаний, номер існує. Решта — мовчки ні.
- **Запас 700 мс** (`LagMs`) — мережа телефона в одну сторону 50–250 мс, пачка намірів клієнта ≤ 80 мс, тік 50 мс, тремтіння.
  Запас нічого не дарує: RTP рахували для того, хто ріже все, а пізніше розрізаний овоч не дає більше за вчасно
  розрізаний. Бот, що ріже все одразу (чи шле всі номери щотіку), — це рівно «ідеальний різник» = 97 %.
- **«Забрати» — без запасу**: дійсне, лише якщо сервер отримав його раніше, ніж вилетів гнилий (як «Забрати» в Лелеці —
  за множником у мить отримання). Будь-який запас тут дав би боту забирати, побачивши гнилого.
- Наперед різати не можна (`t < at` — ні), майбутніх номерів клієнт і не знає.
- Авторізання й автозабір — на сервері, у мить за розкладом (`at + 100`), тож рідкий тік чи пізня дія дають той самий
  підсумок (`Advance` проживає події в порядку часу).

## 6. Протокол

### Дії

| дія | payload | коли | відмова |
|---|---|---|---|
| `start` | `{ amount, auto?: number\|null, autocut?: bool }` | `idle` | раунд іде, вимкнено, поза лімітами, не ціле, кривий авто, бракує черепків, каса |
| `cut` (input) | `{ ids: number[] }` | `fly` | мовчки (§5) |
| `cash` | — | `fly`, M > ×1,00 | «Спершу розріж хоч щось», «Пізно — гнилий уже летить», «Раунд не йде» |
| `auto` | `{ x: number\|null }` | `fly` | кривий x |
| `autocut` | `{ on: bool }` | `fly` | — |

`cash` відповідає тостом «Забрав ×1,13: +113 🏺».

### Вид (`View`, camelCase)

```
{ phase: 'idle'|'fly', now, on, hash,            // hash — поточного раунду (fly) або наступного (idle)
  limits: { min, max }, cap,                     // cap — стеля з конфігу зараз (×)
  wallet, note,
  round: null | { no, stake, auto, autocut, t0, m, win, cap, cuts, tier,
                  strip: [inc…],                 // останні 8 розрізаних приростів (соті)
                  fruits: [{ id, k, inc, at, x0, x1, h, spin, cut }] },   // вилетілі за останні ~3,4 с
  last: null | { no, hash, seed, stake, m, win, why: 'cash'|'rot'|'empty'|'void', cap, potential, codes, seen, cuts,
                 t0, endAt, rot: null | { id, at, x0, x1, h, spin } },
  history: [{ x, win, why }],                    // до 12, найновіше першим
  best: { x, win },
  k: { lead, wave, stagger, fly, lag, autoCut } }
```

`k` — код овоча (§3.1), `inc` — соті, `at` — мс від `t0`, `x0/x1` — частки ширини, `h` — висота верхівки (частка висоти
поля), `spin` — оберти за політ. Позиція: `s = (t − at)/fly`, `x = x0 + (x1 − x0)·s`, `y = −0,1 + (h + 0,1)·4s(1 − s)`
(0 — низ поля). `codes` — уся послідовність раунду (для «що було б далі» й перевірки), `seen` — скільки вилетіло до кінця.

## 7. Глек, ачівки, таблиця, Журнал

- Репліки Глека — у клієнті (бульбашка біля воза): старт, кавун, Глеків кавун, новий ярус («Ярмарок розгулявся!»),
  забрав, гнилий («А гнилий-то я й не помітив!»), віз порожній. У соло балачки столу нема.
- Ачівки (гра просить сама): `kavuny-10` «Кавунова гора» — забрав на ×10+; `kavuny-glek` «Глеків кавун» — розрізав його.
- Таблиця — найбільший чистий виграш раунду (`Ctx.Score`). Свої рекорди — `best` (найбільший множник і виграш).

## 8. Клієнт (`web/games/kavuny.js` + `kavuny.css`)

- Розкладка: угорі — рядок «що зрізав» (останні 8, як ×1,08 ×1,05 …) і великий **«Разом ×1,13»**, праворуч — гаманець і
  виграш. Середина — полотно-прилавок (дерево, вишиванковий пояс, віз із Глеком), овочі малюються процедурно (свої,
  не емодзі): слива, буряк з бадиллям, яблуко, груша, диня, ребристий гарбуз, смугастий кавун (з блиском), Глеків кавун у
  вишиванці; гнилий — темний, з плямами й мухами. Знизу — ставка (−/+ і швидкі суми), велика кнопка
  «Поїхали! / Забрати N 🏺 / ✕», «авто ×X» і «🔪 авторізання».
- Різання: розчерк мишкою (з натиснутою кнопкою), свайп пальцем, тап по овочу (з запасом під палець). Влучання —
  перетин відрізка руху з колом овоча в мить кадру (за годинником сервера). Розрізаний — одразу половинки й сік
  (оптимістично), номер — у пачку `input('cut')` (не частіше раз на 80 мс). Множник — з виду сервера плюс ще не
  підтверджене. Розрізане авторізанням сервер рахує одразу, а серп на екрані проходить, коли овоч трохи злетить (s ≥ 0,26).
- Подвійне натискання відсікаємо: після відповіді на «Поїхали!»/«Забрати» кнопка чекає виду з тіка (≤ 1,5 с).

  у два рядки; горизонтально — поле ліворуч, панель праворуч.

  послідовність у браузері й звіряє з тим, що було (`codes`), і hash — з тим, що показали **до** старту.

## 11. Свідомі рішення (дрібниці)

- **Сумуємо прирости** (×1 + 0,09 + 0,04 = ×1,13), а не множимо — як на картинці Вови й у адаптації.
- **Яруси** ×1/×2/×5/×10 за множником «ідеального різника» і густіші кидки — щоб ×100 було досяжне за ~1,5 хв, а не
  чверть години; мартингал від цього не ламається (шанс рахується з F).
- **Глеків кавун** — +1,00 на першому ярусі (на овочі «×2»), далі множиться ярусом, як усі.
- Програш — у мить **вильоту** гнилого, не приземлення: інакше «побачив — забрав» робило б гру безпрограшною.
- Забрати до першого розрізу не можна; автозабір від ×1,01; автозабір платить фактичний M.
- Перевага дому — окремим кидком на першому овочі (3 %), далі гра чесна; через це гнилий першим — 9,2 % раундів.
- Стеля ×100 типово (не ×1000, як у Лелеки): до ×1000 різати кілька хвилин; можна підняти в конфігу.
- Перерваний перезапуском раунд — анульовано (ставку назад), а не «за поточним множником»: проста й безпечна відповідь,
  на якій не заробиш.
- Звуку свідомо нема.
