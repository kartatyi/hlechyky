# Скирта (`skyrta`) — хвиля «Вечірка й міні-ігри», за мотивами Pack And Pile

Над скиртою їздить сніп туди-сюди — тап, і він падає. Що звисає за край — обрізається й летить униз, скирта
вужчає. Ідеально рівний сніп повертає трохи ширини, серія ідеальних — більше, а три ідеальні поспіль пускають
вітер на сусіда. Хто перший доклав **25 снопів** — виграв; за **90 с** ніхто — виграє вища скирта.

**Одна кнопка** (пробіл / тап будь-де по своєму полю / A на паді) — ідеально на телефоні. Група **Live**, 1–8
гравців (сам — лише з 🤖 ботами), старт господарем. Етап А (сервер + тести) — гілка `party/skyrta`; клієнт
(`web/games/skyrta.js` + `.css`) робить наступний агент — усе потрібне йому описано тут.

Код: `Impl/SkyrtaCore.cs` (рушій — цілі числа, чисті функції), `Impl/SkyrtaBot.cs` (`SkyrtaStack` — скирта
місця, `SkyrtaBot` — бот), `Impl/Skyrta.cs` (фази, ввід, вітер, кінці, вид/кадр, вечірка). Тести —
`tests/Hlechyky.Tests/Games/SkyrtaTests.cs`.

```csharp
new GameInfo("skyrta", "Скирта", "скирту", GameGroup.Live, 1, 8, TickMs: 40, Start: StartMode.ByHost,
    Options: [LiveBots.LevelOption], Hint: "Тап — і сніп падає на скирту; …")
```

## 1. Правила (усі числа — константи `SkyrtaCore` / `Skyrta`)

**Одиниці.** Довжина — «одиниці поля»: поле `fieldW = 1000` завширшки. Час — **мілісекунди гри** від початку
фази `go` (годинник кімнати, `Skyrta.Now()`).

- **Підвалина**: `[baseL = 300, baseW = 400)` — лівий край і ширина. Ширша за `baseW` скирта не буває.
- **Сніп** має ширину верху скирти (`w`). Номер снопа місця `n` — з 1, промахи теж рахуються. Непарний сніп
  виїжджає **зліва**, парний — **справа**.
- **Рух** — центр снопа ходить трикутною хвилею між `lo = 100` і `hi = 900` (`span = 800`); крайні снопи
  звисають за поле — на клієнті поле видно ширше (див. §5). Швидкість — від висоти `h` (скільки вже покладено):
  `v = min(1100, 420 + 28·h)` од/с.
- **Пауза** між снопами: сніп упав о мить `A` → наступний виїжджає о `A + 350` (промах — `A + 900`).
- **Посадка** (`SkyrtaCore.Land`): верх `[pl, pl+pw)`, сніп `[l, l+pw)`.
  - `|l − pl| ≤ tol(v) = 6 + v/40` → **ідеально**: сніп стає рівно на верх, ширина `+6`, а коли це вже
    3-й і далі ідеальний поспіль (`bigFrom = 3`) — `+16`; росте по центру (`newL = pl − ((nw − pw) >> 1)`), не ширше
    `baseW`. У часі допуск — ±40 мс унизу, ±30 мс угорі.
  - Перекриття є → **обріз**: лишається перетин `[max(l, pl), min(l+pw, pl+pw))`, решта — обрізок, що падає.
  - Перекриття нема → **промах**: сніп злітає, верх не змінюється, висота теж, серія — 0.
- **Вітер.** Кожні 3 ідеальні поспіль (3-й, 6-й, 9-й…) — вітер на **сусіда**: наступне місце за колом, що ще
  кладе (не докладене й не покинуте). Налітає через `windDelay = 500` мс (щоб браузер жертви встиг дізнатись) і
  дме `windMs = 3000` мс: сніп жертви їде ×1,5. Вітер іде на години гри, тож переживає й наступний сніп. **Не
  стакається:** поки на сусіді дме чи налітає — новий порив мимо (не сильніше й не довше).
- **Гойдання** з висоти 15 (`h ≥ swayFrom = 15`, тобто 16-й сніп і вище): до центру додається трикутник
  ±`swayA = 22` з періодом `swayP = 1400` мс, у мить виїзду — нуль.
- **Кінець.** Хто доклав `goal = 25` — виграв (кілька в один тик — раніший момент тапу, однаковий — усі).
  Минуло `limit = 90 000` мс — виграє найвища скирта, рівні — ширший верх; ніхто нічого не поклав — нічия.
  Відлік перед грою — 3 с (`ReadyTicks = 75`).
- **Вихід посеред гри** — скирта лишається на полі (позначка «пішов»), але не грає, не виграє й не ловить вітер;
  лишився один — він переміг; у соло з ботами пішла людина — нічия.

## 2. Ввід: `tap {n, t}`

`input('tap', { n, t })` (або `act` — те саме): `n` — номер снопа, що зараз їде у твого місця; `t` — скільки мс
**від виїзду цього снопа** ти тапнув (ціле, 0…600 000). Браузер рахує свій сніп сам (§4) і шле тап миттєво.

Сервер (`Skyrta.Tap`): не той `n` — «Цей сніп уже впав» (повтор/дубль — без змін); мить тапу `A = s0 + t`
притискається до годинника: `A > now + lead(250)` → `A = now`; `A < now − maxLag(1200)` → `A = now − maxLag`;
`A < s0` після цього — відмова. Далі — рівно той самий `Land`, що й у браузері. Притиснули — браузер бачить
інший верх у кадрі й бере його (§4). Нелегальне (не та фаза, не той payload, не граєш) — відмова, вид не міняється.

Дія лобі `bot {on}` — «🤖 + бот» каркаса (`SoloBot`): двоє ботів (`SoloBots = 2`), рівень — опція `botlvl`.

## 3. Вид (`View`, однаковий для всіх — нічого прихованого)

```
{ phase: 'lobby'|'ready'|'go'|'over', party: bool, goal: 25|15, limit: 90000|45000,
  rules: { tickMs, fieldW, lo, hi, baseW, baseL, v0, vk, vmax, gap, missGap, windMs, windDelay, windStreak,
           swayFrom, swayA, swayP, grow, growBig, bigFrom, maxLag, lead },          // сталі SkyrtaCore
  stacks: [8] null | [[l, w], …],     // покладені снопи місця, [0] — підвалина; null — місце не грає
  stats:  [8] null | { perfects, best, misses, winds },
  winner, winners, series, turn: null, botOffer, botWanted, botLvl, bot: [місця ботів],
  frame: <кадр, див. нижче> }
```

Вид шлеться на кожну посадку (`TickResult.Both` у наступному тику) і на зміну фаз. У лобі `stacks` — лише
підвалини тих, хто сів (і ботів, що сядуть).

**Кадр** (`Frame`, кожні 5 тиків = 200 мс і на кожну посадку):

```
{ ph: 0 відлік | 1 гра | 3 зіграно | 4 лобі,
  ms:   годинник гри, мс (на відліку — мінус скільки лишилось),
  left: скільки мс гри лишилось (у фазі 1),
  p:    [8] null | [n, s0, l, w, h, streak, fl],   // сніп, що їде: номер і мить виїзду (мс гри); верх l,w; висота; серія
                                                     // fl: 1 доклав до мети, 2 бот, 4 пішов, 8 вітер дме чи налітає
  wind: [8] null | [a0, b0, a1, b1…],                // вікна вітру на поточний сніп, мс гри
  ev:   [[…], …] }                                   // події за останні 1,5 с, з id — кадри зливаються, відсіюй за id
```

Події: `['l', id, seat, n, A, l, w, nl, nw, kind]` — сніп `n` упав о `A`: був `[l, l+w)`, верх став `[nl, nl+nw)`,
`kind` 0 обріз (обрізок = сніп мінус новий верх), 1 ідеально, 2 промах (летить увесь сніп);
`['w', id, from, to, a, b]` — вітер; `['g', id, seat, A]` — доклав до мети.

## 4. Рушій C# = JS (паритет)

Браузер повторює `SkyrtaCore` дослівно — цілими: `Speed`, `Tol`, `FromLeft`, `Sways`, `WindOverlap`, `Center`,
`Sway`, `Left` (`c − (w >> 1)`), `Land`. У JS — `Math.floor` для ділень (усі над невід'ємними числами;
`Center` рахує `floor(v·(2t + overlap) / 2000)`, далі `% 1600`). Еталон — `docs/games/dev/skyrta-parity.json`
(пише тест `Parity_vectors_match…`; `SKYRTA_PARITY_WRITE=1` — перезаписати): `center` — рядки
`[t, h, n, s0, wa, wb, c]` (`wa = −1` — без вітру; інакше одне вікно `[wa, wb)`) і `land` — `[pl, pw, l, v, streak, nl, nw, kind]`.
Клієнтська перевірка — `docs/games/dev/skyrta-parity.js` (робить агент клієнта, як `rally-parity.js`).

**Свій сніп у браузері.** Годинник гри в браузері: `ms ≈ frame.ms + (performance.now() − коли прийшов кадр)`,
зсув бери найбільший за останні кадри (найменша затримка). Свій сніп малюй з власного `n, s0` (`l = Left(Center(ms −
s0, …))`), на тап — шли `{n, t: ms − s0}`, локально клади `Land` і стартуй наступний: `n+1`, `s0 + t + gap`.
Прийшов кадр, де `p[me].n` збігається з твоїм, — бери з нього `s0, l, w, h` (сервер міг притиснути мить); `n`
у кадрі менший — сервер ще не отримав тап, лиши свій прогноз. Чужі снопи — з кадру тим самим `Center`.

## 5. Клієнт (наступний агент) — що показати

- Скирти всіх поряд (як сусіди в Цеглинах), **своя — велика**; на телефоні — своя на весь екран, чужі —
  мініатюри зверху. Поле по ширині — від `lo − baseW/2` до `hi + baseW/2` (−100…1100), щоб крайній сніп
  влазив. Скирта росте вгору, камера їде за верхом (останні ~8 снопів).
- Обрізок падає й крутиться; ідеальний сніп — спалах «рівно!»; промах — сніп летить донизу; вітер — «💨» над
  скиртою жертви, видно всім (fl 8 і `wind`). Лічильник `h / goal`, час `left`.
- Тап — по всьому своєму полю (≥ 44 px — і так), пробіл, пад: `pad: { a: true, anyBtn: true }` → tap.
- Режим вечірки (`view.party`) — модуль у `HGames.embed`: лише `ctx` і свій `root` (див. party-minigame.md).

## 6. Бот (`SkyrtaBot`)

Знає рух снопа так само, як браузер: раз на сніп (і заново, коли на нього налетів вітер) шукає першу мить від
`react` мс після виїзду, коли лівий край снопа збігається з верхом (`Aim`, крок 4 мс), і додає похибку рівня —
нормальний розкид σ і зрідка грубий промах ±150–350 мс. Тапає тим самим `Tap`, що й людина, рандом — `Ctx.Rng`.

| рівень | react, мс | σ, мс | грубий промах |
|---|---|---|---|
| легкий | 700 (+0…160) | 65 | 7 % |
| звичайний | 430 (+0…160) | 45 | 4 % |
| сильний | 270 (+0…160) | 26 | 2 % |

Заміри (4 боти одного рівня, гонка до 15, 4 сіди): легкий — 30 с до кінця, верх ~41 од, ~2 промахи;
звичайний — 17,5 с, ~116 од; сильний — 14 с, 72 % ідеальних, ~319 од, промахів майже нема.

## 7. Режим вечірки (`IPartyMinigame`, docs/games/specs/party-minigame.md)

- `party=1`: до **15 снопів** або **45 с** (відлік 3 с), без «🤖 + бот» (дія `bot` — відмова, `botOffer: false`).
  Грають **усі місця** `0..Players−1`; на `bots` — `SkyrtaBot` рівня `botlvl`. Людина, що відпала, — її
  скирта просто стоїть.
- `PartyCapMs = 60 000`, `PartyMin = 2`, `PartyMax = 8`.
- Scores: `h·1000 + w` (висота, ширина верху ≤ 400 — тай-брейк). Winners — найкращий score.
- Ні Award, ні Score; Глек — лише раз на промах із шансом 1/2 (без старту, вітру й кінця).
- `Howto`: «Тапни, коли сніп над скиртою: що звисає — обріже, рівно — скирта ширшає. Вище всіх за 45 с (чи 15
  снопів) — перший. Пробіл / тап / A — кинути сніп».

## 8. Ачівки й Глек

Лише у звичайній партії від двох людей, без ботів (`ach:` у `AchievementCatalog`):
`skyrta-line` «Рівно, як під шнурок» — 10 ідеальних поспіль; `skyrta-neat` «Скиртоправ» — доклав 25, жодного
разу не обрізавши більше ніж половину (і без промахів); `skyrta-storm` «Буревій» — тричі пустив вітер за партію.

Глек (`Ctx.Say`): старт — з шансом 1/3; перший промах партії — «Хто так скирти кладе? У мене дід так клав — то вже
на третій день розвіяло»; перший вітер — «💨 Оля пускає вітер на сусіда — Петро, тримай снопи!»; кінець — рядок про переможця.

## 9. Свідомі рішення й ризики

- **Довіра до моменту тапу.** Клієнт може вибрати будь-яку мить у вікні `maxLag` (1,2 с) назад — у теорії
  «ідеальний» тап підбирається скриптом. Для гри друзів прийнятно (як журнали натисків у Цеглинах); вікно
  тримає лише чесну затримку зв'язку. Виграш часу від «старої» миті не накопичується: наступний сніп виїжджає
  від неї ж.
- **Вітер посеред снопа**: браузер жертви дізнається про нього за ~0,5 с до пориву; запізнився — сервер
  поправить верх кадром.
- **Обрізки** — лише подія, на дошці нічого не лежить.
- Без Save/Load (жива гра на хвилину-півтори).
