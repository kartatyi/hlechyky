# Забіг дня (`dino-daily`) — хвиля 2, пакет «runner»

Соло-версія Стрибозаврів: одна криза на день для всіх, лавина лише тисне ззаду, рахунок — метри. Механіка,
одиниці, фізика, курс, протокол `in/ping`, перемотування, передбачення, клієнтські шари й звук —
**повністю** з [`dino.md`](dino.md) (§2.1–2.6, §3.1, §3.3, §5, §6). Тут — лише різниця і те, як гра лягає на
соло-каркас (ключ, збереження, таблиця, нагорода). Файли — `dino.md` §0: клас `DinoDaily` у `Impl/Dino.cs`,
другий `HGames.register` у `web/games/runner.js`, тести `DinoDailyTests.cs`.

## 1. Суть і чому це весело

Зайшов на хвилину — пробіг, побачив «Оля сьогодні 2 475 м», пробіг ще. Траса та сама для всіх до
київської півночі, тож можна порівнювати чесно і навіть підказувати одне одному в балачках («на 1 200 м
яма одразу після гірки»). Спроб скільки завгодно, у таблицю йде найкраща за день. Лавина тисне так само,
як у партії: кожен спотик — ближче; дожене — забіг скінчився. Густина перешкод росте й далі після 90-ї
секунди, тож нескінченного забігу нема — але 5 км для впертих реальні.

### GameInfo

```csharp
public override GameInfo Info { get; } = new(
    "dino-daily", "Забіг дня", "забіг дня", GameGroup.Solo, 1, 1,
    TickMs: RunnerSim.TickMs /* 40 */, Start: StartMode.Immediate,
    Hidden: false, Private: true, Persistent: true, Rated: false, Score: ScoreOrder.HigherIsBetter,
    Options: null,
    Hint: "Та сама криза для всіх на цілий день. Скільки метрів пробіжиш від лавини? Спроб скільки завгодно, у таблицю йде найкраща",
    Client: "runner");
```

- **Не `IDailyGame`** — свідомо (§9.1): панель «Щоденний глек» читає соло-результат як «спроби, якщо < 1000,
  інакше мілісекунди», і метри вона б показала брехнею. Натомість гра — звичайна соло з
  `Score: HigherIsBetter`: каркасна «Таблиця → Забіг дня → за день» показує саме метри (`best`) і кількість
  спроб (`tries`), без правок спільних файлів. Період «за день» у `Leaderboards.Since` — київський день, той
  самий, що в ключі.
- `SoloKey(nickKey, clock) => $"dino-daily:{Days.Today(clock)}:{nickKey}"` — з днем, але **без** префікса
  `daily:` (інакше `Rewards.Solo` записав би метри в `daily_results` як спроби). Новий день — новий ключ —
  нова кімната з новою трасою; вчорашня, якщо відкрита, доживає своє (§9.4).
- `SeatName(0)` → «стрибозавр». Динозавр — завжди колір/візерунок місця 0 (зелений).
- `Persistent: true` — крихітний стан §2.5. `Private: true` — у лобі кімнати нема, дивитись може лише сам
  (подія `solo` покаже друзям «Оля зараз у Забігу дня»).

## 2. Правила — різниця від партії

### 2.1 Одна спроба = одна партія каркаса

Кімната відкривається `OpenSolo` → `Start()` → фаза `wait`. Перший стрибок починає біг; лавина дожене →
`Ctx.Finish` → статус `finished` → каркасна кнопка «Ще раз» (у `core.js` вона є для соло, що не `daily`) →
`Rematch` → `Start()` → знову `wait`. Так кожна спроба зберігається (`Save()` на `Finish`), а тиків між
спробами нема зовсім (`Finished` кімнати каркас не тикає) — соло-кімната, що живе 30 хвилин без людини,
нічого не коштує.

| Фаза | Що | `TickResult` |
|---|---|---|
| `wait` | динозавр стоїть, курс від зерна дня вже згенеровано на 1600 px уперед і видно; `s = 0`, `run = 0`; чекаємо ребро стрибка | `None` (нічого не рухається) |
| `run` | біг, як у партії; `ReadySteps = 0`, тож `run = s` | `FrameOnly` кожен тик; **перший** тик бігу — `Both` (вид із `ph: "run"`, щоб F5 посеред бігу зібрав сцену правильно) |
| `done` | забіг скінчився: підсумок; це `RoomStatus.Finished` | (тиків нема) |

Перший `Input("in", { s: 0, k: 5 })` у `wait` → фаза `run`, ввід записано на крок 0 (стрибок на першому
кроці — динозавр стартує зі стрибка, як у Chrome). Наступний тик сервера робить кроки 0 і 1. Клієнт
починає свій годинник із `cs = 0` у мить натиску — і опиняється попереду сервера рівно на потрібний `lead`
(`dino.md` §5.6).

### 2.2 Світ і лавина

Ті самі `Speed0/SpeedMax/RampSteps`, `paceX`, `D(run)` (`dino.md` §2.2): лавина стартує за 560 px, підходить
на 2,5 px/с і зупиняється за 200 px на 144-й секунді. Різниця в прогресі курсу: **`PmCap = 1250`** (у партії
1000) — після 90-ї секунди густина росте ще до 112,5-ї: `gmin = 60 − 28·1,25 = 25` кроків (0,5 с), `gmax =
100 − 50·1,25 = 37` (0,75 с) при 700 px/с — низькі брили через 350–520 px, «тап-тап-тап». Далі не густішає
(тап у повітрі 320 px — межа людського). `RoundCap` **нема**: біг триває, поки не дожене лавина.

### 2.3 Підбирачки

🥚 яйце і 🌶 перчик — як у партії (`dino.md` §2.6). ❄ сніжки не випадає взагалі (кидати нема в кого; у
генераторі `snow → egg`, як при опції `snow = off`), дії `throw` нема («Тут так не ходять»). Яйця — лічильник
для підсумку й ачівки; **на метри не впливають**.

### 2.4 Рахунок і кінець спроби

Лавина дожене (`lag ≥ D(run)`) → `meters = paceX(run+1) / 320` (цілі метри) →

```
runs++; eggsTotal += eggs; best = max(best, meters)
Ctx.Score(0, meters)                                   // AddSolo лишає найкраще за (ключ:день, нік), tries++
якщо meters ≥ 500 і ще не платили сьогодні (прапорець paid): Ctx.Award(0, 0, "daily:dino-daily"); paid = true
якщо meters ≥ 2000: Ctx.Award(0, 0, "ach:dino-far")   // ачівка сама не подвоюється
якщо meters > bestBefore і meters ≥ 1000 і з останнього рядка минуло ≥ 60 с (за Ctx.Clock):
    log = $"Забіг дня: {нік} — {meters} м, особистий рекорд дня"; loggedAt = now   // після рецензій: не «найкращий сьогодні»
Ctx.Finish([0], log)                                   // без рядка, якщо log порожній
```

- `Ctx.Score` з `Key = "dino-daily:<день>:<нік>"` → `Rewards.Solo`: ключ не починається з `daily:` → звичайний
  соло-рядок `room_id = <ключ>:<день>`, `outcome = solo`, `score = meters`, `tries + 1` на кожну спробу —
  саме те, що показує таблиця («рекорд», «спроб»). У `daily_results` нічого не пишеться (і не треба).
- `Ctx.Award(0, 0, "daily:dino-daily")` → `Rewards.Award` бачить префікс `daily:` → платить типову
  `Economy:DailyReward` з ref `daily:dino-daily:<сьогодні>:<нік>` — раз на день на нік, повтор — `Duplicate`.
  Прапорець `paid` у збереженні лише економить виклик.
- Поріг 500 м на нагороду — щоб «стрибнув-упав» не платило.
- `Finish([0], log)` для одного ніка: `Rewards.Finish` виходить одразу (менше двох ніків), рейтингів і
  черепків за партію нема — тільки соло-рядок і щоденна нагорода. Другого `Finish` за спробу не буває.

### 2.5 Збереження (`Persistent`)

`Save()` → `{"day":"2026-09-27","best":2475,"runs":7,"eggs":12,"paid":true,"loggedAt":"2026-09-27T14:03:11+00:00"}`
(camelCase, `JsonSerializerDefaults.Web`). `Load(json)`: день не збігається з днем ключа кімнати (`_day`,
виставлений у `Start()` з `Days.Today(Ctx.Clock)` раз і назавжди, як у Глек-слова) → ігнорувати; інакше
відновити `best/runs/eggs/paid/loggedAt`. Стан пишеться каркасом на кожному `Finish` (`RoomContext.Store`),
тобто після кожної спроби; `Input` не зберігає нічого, і це правильно — посеред бігу зберігати нема чого.

Кімната після `Finish` живе ще 15 хвилин (`FinishedLife`), потім прибирається; наступний `OpenSolo` того ж
дня створює нову з тим самим ключем і піднімає збереження — `best`, `runs` на місці.

### 2.6 Зерно дня

`seed = Days.Seed("dino-daily", день)` (`Contracts.cs`) — однакове для всіх до київської півночі; у виді
відкрито (клієнт будує курс сам). Дізнатись трасу наперед можна лише пробігши її — і це чесно, вона одна на
всіх.

### 2.7 Вихід, F5, «Ще раз», один гравець

- «Закрити» (LeaveRoom) посеред бігу — `Vacate` для соло не кличе `OnLeave`, кімната зникає; спроба не
  зараховується (лавина її не дожене, `Finish` не буде). Свідомо: закрити вкладку = не дограв.
- F5 посеред бігу — динозавр біжить без керма й за 1–3 с вибуває; спроба зарахується (як є). На реконекті
  клієнт шле `k = 0` і продовжує з виду.
- «Ще раз» — §2.1. ~~Після півночі за Києвом «Ще раз» на вчорашній кімнаті біжить вчорашню трасу, результат —
  під вчорашнім ключем.~~ **Після рецензії:** так не виходило — каркас пише соло-рядок із днем *запису*
  (`{ключ}:{Days.Of(At)}`), а таблиця «за день» відбирає за `created_at`, тож учорашня траса лягала в СЬОГОДНІШНЮ
  таблицю. Тепер `Start()` помічає, що київський день змінився, і переходить на новий: нове зерно, рекорд, спроби
  й нагорода дня з нуля (див. «Як реалізовано», п. 6).
- Гравець тут завжди один; вихід «посеред партії» техпоразкою бути не може.

### 2.8 Дядько Глек

Соло — балачки столу нема (`room.Talks == false`), `Ctx.Say` мовчить. Про рекорд каже Журнал (§2.4).

## 3. Дії й payload

- `Input("in", { s, k })` — `dino.md` §3.1; у `wait` приймається лише `k` з бітом ребра (`4`), він і
  запускає біг; утримання без ребра в `wait` ігнорується. У `done` — відкидається.
- `Input("ping", { t })` — §3.3.
- `throw` і все інше → «Тут так не ходять». Через `Act` ще й «Тут так не ходять» тостом — але клієнт `Act`
  сюди не шле.

## 5. Модель симуляції й мережа

`dino.md` §5 без змін. Особливості: `ReadySteps = 0`, `RoundCap = 0` (нема), `PmCap = 1250`, `players = 1`,
зерно — дня. Бюджет тика на одному гравцеві мізерний (≤ 0,05 мс); перф-тест усе одно є, бо соло-кімнат
може бути десяток одночасно (усі друзі ввечері): `Ten_daily_rooms_ticking_together_cost_under_a_millisecond_per_tick`.

Клієнт у `wait` тримає власний годинник на 0 і не шле `in`, доки не буде ребра; `ping` шле й у `wait`, щоб
`lead` на старті вже був виміряний.

## 6. Клієнт — різниця від партії

- **Зверху ліворуч великі метри** `754 м` (моноширинні цифри, тонкий пробіл тисяч), під ними дрібно «рекорд
  дня 2 475 м · спроба 8»; праворуч — 🥚 лічильник спроби. Смужка гонки `.rnr-strip` — лише лавина і ти.
- У `wait` на канвасі підказка: «Пробіл, ↑ або тап — і побігли. Тримай довше — стрибнеш вище».
- Після спроби (`done`) — `.rnr-over` з підсумком: «1 234 м · 🥚 2» (або «🏆 новий рекорд дня: 2 475 м»),
  **таблиця «сьогодні»** — до 10 рядків з `GET /api/games/leaderboard?game=dino-daily&period=day` (заголовок
  `X-Nick: encodeURIComponent(me.nick)`, як у `clicker.js`), колонки «нік · м · спроб», свій рядок обведений;
  кнопка каркаса «Ще раз» під нею; **Пробіл/Enter/тап по канвасу/Ⓐ** у `done` → `HGames.call('Rematch',
  ctx.room.id)` (кнопку каркаса дублюємо, бо після смерті рука вже на пробілі). Таблицю перечитуємо не
  частіше ніж раз на 10 с (кеш у стані картки).
- «Закрити» — кнопка каркаса.
- Керування — `dino.md` §6.5 без сніжки: `pad: { dirs: 'y', a: 'Space', anyBtn: true, hint: '{a} стрибок (тримай — вище) · {dpad} ↓ пригнутись' }`.
- Статуси: `wait` — «Пробіл, ↑ або тап — стрибок і старт. Тримай довше — вище»; `run` — «↓ пригнутись ·
  лавина за 342 м» (округлено до метрів `(D − lag)/320`); `done` — «1 234 м · рекорд дня 2 475 м · спроба 8».
- `news`:

```js

    '📅 Одна траса на день для всіх — порівняй метри з друзями в Таблиці',
```

- Іконка — та сама, що в `dino`, з маленьким календарним квадратиком у куті (`rect 10 10 5 5` кольору

## 9. Ризики й свідомі рішення

1. **Не «Щоденний глек», а соло-таблиця.** Панель щоденних живе на домовленості «< 1000 — спроби, ≥ 1000 —
   мс» і показувала б 2 475 м як «2,5 с». Без правок `Daily`/`Rewards` метри чесно показує лише каркасна
   «Таблиця → за день» (`best`, `tries`). Ціна: гри нема в панелі щоденних, серії днів (🔥) не рахуються.
   Бажання до каркаса — `IDailyGame` з видом результату «дистанція» (або `SoloScoreEvent.Unit`); тоді досить
   буде додати маркер і префікс ключа.
2. **Кожна спроба — `Finish`**, а не внутрішній рестарт. Плюси: збереження на кожній спробі, нуль тиків між
   спробами, каркасне «Ще раз». Ціна: на кожен `Finish` каркас шле `rooms` усім (кімната приватна, у списку її
   нема, але подія летить) — десяток спроб на хвилину на всіх друзів = десяток коротких подій; лобі до
   цього звикло (кожен вхід/вихід за стіл робить те саме).
3. **Ліміту спроб нема** — бриф так і просить; фарму черепків нема (нагорода раз на день, за партію соло
   не платять).
4. **Вчорашня кімната після півночі** ~~доживає з учорашнім ключем: результат піде «за тиждень»~~ — після
   рецензії «Ще раз» у ній дає вже сьогоднішню кризу (п. 6 «Як реалізовано»). Клієнт після півночі показує в HUD
   «настав новий день — «Ще раз» дасть нову кризу» (посеред бігу — «це ще вчорашня траса…»), коли
   `view.day != Days.Today` (день бере з `Date` браузера у київському часі:
   `new Date().toLocaleDateString('sv-SE', { timeZone: 'Europe/Kyiv' })`).
5. **F5 = спроба зіпсована**, закрив вкладку = спроби не було. Паузи в забігу від лавини бути не може.
6. **Тиша в Журналі**, крім нового рекорду дня від 1000 м і не частіше ніж раз на хвилину — щоб уперті не
   заливали Балачки.
7. **Стеля густини 1250 ‰** робить забіг скінченним і для ідеального гравця (≈ 5–6 км, 3–4 хвилини); ліміту
   часу нема, бо він убив би відчуття «ще трохи».
8. **Соло-реалтайм — перша така гра на платформі**: `TickEngine` тикає й соло-кімнати; нуль тиків у `wait`
   (`None`) і `Finished` після кожної спроби гарантують, що десяток покинутих кімнат нічого не коштує.

## Як реалізовано (27.09.2026, гілка `wave2/runner`)

Клас `DinoDaily` — у `Impl/Dino.cs` поруч зі Стрибозаврами, на тому самому `RunnerSim` (режим `Dino`,
`ReadySteps = 0`, `PmCap = 1250`, сніжок нема); клієнт — другий `HGames.register` у `runner.js`. Усе, що
спільне з партією (крокомір за стінним годинником, випередження годинника клієнта, поле `hs` у кадрі,
оговтування після спотику, бирки, кільце під ногами), описано в `dino.md` → «Як реалізовано», пункти
1–5, 11, 13, 19–20. Тут — лише своє.

### Відхилення й уточнення

1. **Таблиця — каркасна соло-таблиця «за день»** (`HigherIsBetter`, ключ `dino-daily:<день>:<нік>` без
   `daily:`), як і задумано в §9.1: панель «Щоденний глек» гру не показує, зате метри в таблиці — чесні метри.
   Спільних файлів для цього правити не довелось.
2. **Старт — перший натиск, годинник клієнта одразу стає на випередження** (`dino.md` п. 13): сервер у `wait`
   не тикає зовсім (`TickResult.None`), перший `in` з ребром переводить у `run` і записує стрибок на крок 0;
   клієнт у ту ж мить робить крок і наздоганяє `lead` — ні снапу, ні виправлення на старті.
3. **Ввід без ребра в `wait` відповідає «Стрибни, щоб побігти»**, у `done` — «Забіг скінчився — тисни «Ще
   раз»» (через хабовий `Input` цього ніхто не бачить, але `Act` і тести бачать).
4. **Таблиця «сьогодні» в підсумку** перечитується одразу після кожної спроби (зміна `runs`) із запасом
   0,7 с — рядок у базу каркас пише вже після `Finish`; далі — не частіше ніж раз на 10 с.
5. **Підказка «це вчорашня траса — зайди з лобі за новою»** з'являється в HUD, коли `view.day` не збігається
   з київською датою браузера (§9.4).

6. **Після рецензій — «Ще раз» через північ біжить сьогоднішню кризу.** Рецензія коду відтворила: кімната,
   відкрита о 23:58, після рематчу в 00:03 давала вчорашнє зерно, вчорашній `best`/`runs`/`paid`, а метри лягали в
   сьогоднішню таблицю (каркас пише рядок із днем запису). `Start()` тепер порівнює `_day` з `Days.Today(Ctx.Clock)`
   і, якщо день новий, скидає рекорд, спроби, яйця, нагороду й час рядка Журналу. Збереження пишеться під ключем
   кімнати (учорашнім) — нешкідливо: сьогоднішній вхід з лобі відкриє кімнату з сьогоднішнім ключем, а рядки
   таблиці однаково вже в сьогодні. Тест `Rematch_after_kyiv_midnight_runs_the_new_day_with_a_fresh_record_and_reward`
   без правки падає. Підказка в HUD після півночі — «настав новий день — «Ще раз» дасть нову кризу».
7. **Одна кнопка — нова спроба.** Стрибок, тап чи Ⓐ після кінця (не раніше 0,7 с, щоб натиск «ще з гри» не ховав
   підсумок) шле `Rematch`, і щойно приходить вид із `wait`, той самий натиск стартує забіг (раніше перший тап
   ховав підсумок, другий стартував).
8. **Привид своєї найкращої спроби дня.** Клієнт пише свій ввід (`[крок, клавіші]` на кожну зміну) і після кінця
   спроби, якщо вона найкраща сьогодні на цьому пристрої, проганяє журнал з нуля на власному `Sim` і звіряє метри з
   тими, що порахував сервер (`view.last.m`): збіглось — кладе в `localStorage` (`runner.ghost`: день, метри,
   журнал; ~1 КБ на хвилину бігу). Наступна спроба того ж дня бере журнал і крокує другий `Sim` поруч зі своїм (один
   зайвий крок на 20 мс, без алокацій): блідо-крижаний динозавр із биркою «👻 2 838 м» біжить трохи «вглибині»
   кризи, спотикається там, де спотикнувся «оригінал», і відстає або тікає. Спроба з F5, снапом чи відкинутим
   сервером вводом не зійдеться — і привидом не стане. Лише свій і лише на цьому пристрої (без сервера й бази).
9. **Рядок Журналу — «особистий рекорд дня»**: «найкращий сьогодні» читали як рекорд дня серед усіх.
10. **Статус** посеред бігу — «🌨 лавина за N м», а «пригнись!» — лише перед бурулькою чи птеродактилем (раніше
    «↓ пригнутись» висіло весь забіг і читалось як наказ); на паді — «Ⓐ — стрибок і старт».
