# Гончарне коло (`clicker`) — пункт 82

**Info:** `Id="clicker"`, `Title="Гончарне коло"`, `Accusative="гончарне коло"`, `Group=Solo`, 1/1,
`Start=Immediate`, `Private=true`, `Persistent=true`, `Score=HigherIsBetter` (усього глеків за весь час),
`Hint="Крути коло, ліпи глеки. Глеки — у черепки, черепки — у гаманець. Коло крутиться і без тебе, поки ти слухаєш радіо"`.
Ключ кімнати: `clicker:<nick_key>` (один назавжди). Валюта гри — **глеки** (не черепки).

## Механіка

- `Save()`-стан: `{ pots: long, total: long, lastSync: iso, upgrades: { wheel: n, apprentice: n, kiln: n, clay: n }, soldToday: { day, shards }, clicksWindow: [...] }`.
- **Клік** — `Act('spin', { n })`: додає `n × perClick` глеків. Захист: сервер приймає ≤ 12 кліків/с (рахує
  за `Ctx.Clock` у ковзному вікні 1 с; надлишок мовчки відкидає) — клієнт може батчити (`n` до 12) раз на
  секунду замість 12 повідомлень. `perClick = 1 + wheel`.
- **Пасивний дохід**: `perSecond = apprentice × 0.5 + kiln × 3` глеків/с. Рахується **сервером** при кожній
  дії/відкритті як `(now − lastSync) × perSecond`, але не більше ніж за **8 годин** офлайну (щоб не було
  мільйонів після відпустки) — і лише якщо гравець був онлайн на радіо в цей час? Ні — простіше: пасив іде
  завжди, стеля 8 год. «Поки слухаєш радіо» — це `Ctx`-незалежно; підказка каже м'якше.
- **Апгрейди** (за глеки, ціна росте ×1.5 за рівень, округлення вгору):
  | key | назва | база | ефект |
  |---|---|---|---|
  | wheel | Швидше коло | 15 | +1 глек за клік |
  | apprentice | Підмайстер | 100 | +0.5 глека/с |
  | kiln | Піч | 1 000 | +3 глеки/с |
  | clay | Гарна глина | 10 000 | ×1.25 до всього (мультиплікативно, макс 5 рівнів) |
- **Продаж**: `Act('sell', { pots })` — обмін 100 глеків → 1 черепок через `Ctx.Award(0, k, "clicker")`
  (проходить через стелю `ClickerDailyCap=20`/день у WP1; гра сама теж лічить `soldToday`, щоб показати
  «сьогодні ще можна продати N»). Кратно 100.
- `Ctx.Score(0, total)` після кожної дії (таблиця «Гончарі» за `total`). Ачівки `potter-1k`, `potter-100k` — WP1.
- Скидання нема.

## Дії

`spin {n}`, `buy {key}`, `sell {pots}`.

## Вид

```ts
{ pots, total, perClick, perSecond, upgrades: { key: { level, price, name, desc } },
  canSellToday: number, soldToday: number, cap: 20, rate: 100, lastSync }
```

## Клієнт

- Велике коло (CSS-обертання, швидкість від `perSecond`), при кліку/тапі — «стук» (scale) і +N, що
  вилітає. Лічильник глеків із плавним доліком на клієнті за `perSecond` між синхронізаціями (сервер — джерело
  правди: після `room`-події значення підганяється). Кнопки апгрейдів з цінами, «Продати 100 → 🏺1» (і «все»).
  Батчинг кліків: рахувати локально й слати `spin {n}` раз на 700 мс.

## Тести (≥ 20)

- Клік додає perClick; > 12/с відкидається (FakeClock).
- Пасив за час; стеля 8 год; апгрейди міняють perClick/perSecond; ціни ×1.5; clay ×1.25 (макс 5).
- Продаж: кратність 100; `Award` з правильною кількістю; ліміт 20/день у власному лічильнику (WP1 — своя
  стеля); `Load(Save())`; `Score` = total.
- Детермінізм не потрібен (немає випадковості).
