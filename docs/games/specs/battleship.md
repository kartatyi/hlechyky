# Морський бій (`battleship`) — пункт 15

**Info:** `Id="battleship"`, `Title="Морський бій"`, `Accusative="морський бій"`, `Group=Board`, 2/2,
`Hidden=true`, `Rated=true`, `Hint="Розстав кораблі, стріляй по чужому полю. Влучив — стріляєш ще"`.
`SeatName`: «синій»/«червоний» (кольори — `--accent` не треба: чіп-класи `x`/`o` як у каркасі).

## Правила

- Поле 10×10 (a–k без «й»? ні — колонки латиницею a–j, рядки 1–10; у виді індекс 0..99).
- Кораблі: 1×4, 2×3, 3×2, 4×1 (класика). Не торкаються навіть кутами.
- **Фаза розстановки.** Обидва гравці розставляють одночасно (гра стартує в фазі `placing`). Дії:
  `place` з повною розстановкою (валідність перевіряє сервер), `random` (сервер сам розставляє з `Ctx.Rng`),
  `ready`. Коли обидва `ready` → фаза `battle`, першим стріляє місце 0 (у рематчі — обертання каркасом).
  Таймер розстановки — 120 с (за `Ctx.Clock`; перевіряти в `Act` і в `Tick` — гра має `TickMs=1000`): хто не
  готовий — отримує випадкову розстановку автоматично.
- **Бій.** `shoot {cell}`: промах → черга суперника; влучив → стріляєш ще; потопив → ще, клітинки навколо
  корабля позначаються промахами автоматично (у виді). Повторний постріл у відому клітинку — Fail.
- Перемога — усі 10 кораблів суперника потоплені. Вихід — техпоразка.

## Дії

| action | payload |
|---|---|
| `place` | `{ ships: [{ cells: number[] }] }` — 10 кораблів; сервер перевіряє склад, прямолінійність, дотики, межі |
| `random` | — |
| `ready` | — (потрібна валідна розстановка) |
| `shoot` | `{ cell: number }` |

## Вид (`Hidden`)

```ts
{
  phase: 'placing'|'battle'|'done',
  turn: 0|1|null,                     // null у placing
  placeUntil: string|null,            // ISO, кінець таймера розстановки
  me: null | {                        // тільки для сидячого; глядач — null
    ships: number[][],                // мої кораблі
    ready: boolean,
    hits: number[], misses: number[]  // куди суперник уже стріляв по мені
  },
  enemy: {                            // моє знання про поле суперника (глядач бачить обидва «enemy»-подання без кораблів)
    hits: number[], misses: number[], sunk: number[][],   // sunk — повні клітинки потоплених
    ready: boolean, left: number      // скільки кораблів ще на плаву
  },
  boards?: [enemyLikeA, enemyLikeB],  // тільки для глядача (seat == null): обидва поля в «enemy»-форматі
  shots: number,                      // усього пострілів у партії
  result: null | { winner: 0|1, shots: [number, number] }
}
```
**Тест на приховування:** у `View(1)` немає `ships` місця 0 ні в якому полі; у `View(null)` — жодних `ships`.

## Клієнт

- Два поля поряд (на вузькому — одне під одним): «Моє» і «Чуже». У `placing`: перетягування зі списку
  кораблів або кнопки «Випадково» + «Готово»; поворот корабля — клік по ньому. У `battle`: клік по «Чужому».
- Влучання — `--clay` крапка, потоплений — заливка `--danger`, промах — маленька крапка `--muted`.
- Анімація «бризки» на промах не обов'язкова.

## Тести (≥ 25)

- Валідатор розстановки: правильна проходить; дотик кутами — Fail; корабель за межами; неправильний склад;
  не прямий корабель.
- `random` 200 разів із різними сідами → усі валідні.
- Таймер: `Tick` після 120 с → неготовим дано випадкове, фаза battle.
- Постріл не в свою чергу; повторний постріл; влучання дає ще хід; потоплення позначає околиці; перемога
  після 20 влучань.
- Приховування у видах; глядач бачить обидва поля без кораблів.
- Виплата: `MinRewardMoves=10`.

### Сервер

- `GameInfo`: `battleship`, Board, 2/2, `TickMs: 1000`, `Hidden: true`, `Rated: true`. Місця — «синій»/«червоний».
- Правила винесені в статичний `BattleshipRules`: поле 10×10, флот `[4,3,3,2,2,2,1,1,1,1]`, `Halo`,
  `Around`, `Invalid` (валідатор із людськими текстами помилок), `RandomFleet(Random)`.
  `RandomFleet` кладе кораблі разом з околицями в маску зайнятого, тож дотик просто не трапляється;
  спроби обмежені (200 заходів × 500 спроб на корабель), у найгіршому разі повертається ручна
  розстановка `Canonical()` — гра не має права зациклитись.
- Стан партії — два `Side` (кораблі, `Ready`, `Hits`, `Misses`, `Shots`). `Save()`/`Load()` є, хоча гра не
  `Persistent`: це дешева страховка й окремий тест на еквівалентність виду.
- Дії: `place` (`{ships:[{cells}]}`, голий масив теж приймається), `clear`, `random`, `ready`, `shoot`
  (`{cell}` або голе число). Тексти відмов короткі: «Зараз не твій хід», «Сюди вже стріляв», «Кораблі не
  можуть торкатись навіть кутами».
- `clear` понад spec: «Скинути» в браузері стирає розстановку, і сервер мусить забути її разом із людиною —
  інакше таймер дочекався б кінця й повів у бій із флотом, який гравець уже вважає стертим. Модуль шле
  `clear` щоразу, коли розстановка перестала бути повною (`Скинути`, знятий з поля корабель).
- Час на розстановку перевіряється і в `Tick`, і на вході в `Act`: між тиками ціла секунда, і за неї
  ніхто не має права ані переставити кораблі, ані сказати «Готово» після дзвінка.
- `left` чужого поля у фазі `placing` — завжди десять (`LeftOf`). «Скільки на плаву» до першого пострілу
  просто нема сенсу, а справжнє число (нуль, доки суперник не розставився) було б і брехнею на екрані,
  і підказкою про чужий поступ. У бою й після нього — справжнє.
- Потоплений корабель одразу обводиться промахами (`Around`), тож у «чуже поле» більше нема куди марно бити.
- Кінець: `Ctx.Finish([переможець], "Морський бій: <нік> синій 10:<скільки потопив суперник> <нік> червоний,
  пострілів N")`. Черепки платить каркас із `RoomFinishedEvent` — гра `Award` не кличе.
- Вихід посеред партії — типовий `OnLeave` каркаса (техпоразка).

### Таймер розстановки і чому Tick повертає View

`TickMs = 1000`, кінець фази — `Ctx.Clock.UtcNow >= _placeUntil`. Через `TickMs > 0` каркас вважає гру
реалтайм-ігрою, а `Rooms.Act` таким **не шле `RoomViews` після ходу** (і не рахує `Moves`). Тому гра
тримає прапорець «стан змінився» і роздає види з `Tick()`:

- розстановка, час не вийшов → `FrameOnly` (у кадрі відлік і хто вже готовий);
- щось змінилось після останнього тика → `Both`;
- бій без змін → `None` (кімната мовчить).

Наслідок, помітний оком: після пострілу поле оновлюється не миттєво, а з наступним тиком (до 1 с). Щоб
клік не здавався мертвим, модуль одразу малює «в польоті» (жовта крапка, що блимає), а сервер шле в
`ActResult` короткий текст — «Влучив! Стріляй ще», «Мимо», «Потопив! Стріляй ще» — і людина бачить його
тостом одразу. Тест `Views_after_a_shot_come_with_the_next_tick` цю домовленість фіксує.

Поки постріл у польоті, чуже поле замкнене **цілком**, а не лише в обстріляній клітинці: `ctx.myTurn`
рахується з виду, тобто після промаху ще секунду каже «твій хід», і другий клік поспіль повертався б
червоним «Зараз не твій хід» у цілком нормальній грі. Ціна — після влучання наступний постріл чекає на
той самий тик, що й так малює влучання.

### Відхилення від spec

1. **Таймер лишає чужу працю.** Spec каже «хто не готовий — отримує випадкову розстановку». Реалізовано
   м'якше: випадкову дістає лише той, у кого розстановки нема або вона нелегальна; хто встиг розставити,
   але не натиснув «Готово», іде в бій зі своєю. Викидати готовий флот через невчасний клік нечесно.
   Обидві гілки покриті тестами (`The_placing_timer_scatters_a_fleet_for_whoever_did_not_place`,
   `The_timer_keeps_the_fleet_of_someone_who_placed_but_forgot_to_press_ready`).
2. **`boards` у виді сидячого — `null`, а не відсутнє поле.** Форма виду стала: серіалізатор пише
   `"boards": null`. Для глядача `enemy` — це `boards[1]` (те саме поле другого місця), щоб набір полів
   не залежав від того, хто дивиться.
3. **Розстановка не перетягуванням, а тапом.** Замість drag'n'drop: тап по кораблю в списку обирає його
   (повторний тап кладе його боком), тап по своєму полю ставить, тап по вже поставленому кораблю
   повертає його, а якщо повернути нема куди — забирає назад у список. Однопалубний крутити нема як, тож
   тап по ньому одразу забирає його назад: інакше корабель «повертався» б сам у себе і зняти його з поля
   не вийшло б нічим. На телефоні це надійніше за перетягування, і воно так само працює мишею. Кнопки
   «Випадково» і «Готово» — як у spec, плюс «Скинути» (стирає і на екрані, і на сервері — див. `clear`).
4. **`MinRewardMoves = 10` не працює за призначенням.** У ігор з `TickMs > 0` каркас не рахує ходів
   (`RoomFinishedEvent.Moves == 0`), тож нагороду відмикає час (`MinRewardSeconds = 20`). Справжня партія
   в морський бій триває хвилини, тож черепки нараховуються; перевірено тестом
   `A_played_out_game_is_long_enough_to_pay_for_itself` і руками (гаманець виріс після партії).

### Потрібно від каркаса (на майбутнє, обхід є)

`Rooms.Act` пов'язує «слати види після ходу» з `TickMs == 0`. Покрокова гра з таймером (морський бій,
а далі — шахи з годинником) хотіла б окремого прапорця в `GameInfo` («ходи покрокові, тик лише для часу»),
щоб вид летів одразу після `Act`. Поки що обхід — прапорець усередині гри й `TickResult.Both` із тика.

### Як перевірити руками

Сервер зі свого worktree на 8103 (`appsettings.Local.json`), одна вкладка — гравець, другий гравець і
глядач заходять окремими з'єднаннями хаба з іншим ніком.

1. «Ігри» → «Настільні» → «+ Стіл» на «Морському бої». Другий сідає — з'являються два поля, список із
   десяти кораблів, кнопки «Випадково»/«Скинути»/«Готово» (остання сіра) і дуга-відлік на 120 с.
2. Тапнути 4-палубний, тапнути `a1` — корабель ліг. Так усі десять; «Моє поле 10 з 10», «Готово» ожила.
   Тап по кораблю повертає його, ще один — назад; тап по однопалубному забирає його назад у список
   («Забрав корабель назад», «Готово» знову сіра).
2а. «Випадково» → повний флот; «Скинути» → поле справді порожнє і лишається таким (перевірити ще й через
   секунду-дві, коли прийде свіжий вид: сервер про той флот теж уже не знає).
3. Обидва «Готово» → фаза бою, «Твій хід» у синього, чуже поле стало клікабельним.
4. Постріл повз — жовта крапка одразу, за секунду сіра крапка й «Ходить <нік>». Влучання — глиняна крапка
   і хід лишається. Потоплення — червона заливка й околиці стають промахами, «Чуже поле» рахує вниз.
   Поки постріл у польоті, чуже поле не клікається зовсім — червоного «Зараз не твій хід» бути не мусить.
5. Потопити всі десять — «Перемога: <нік>», рядок у Журналі, тост гаманця, кнопка «Ще раз».
6. «Ще раз» — місця обернулись, поля чисті, флот знову в списку (окремо перевірено, що старий флот у
   браузері не лишається).
7. «Встати» посеред партії — техпоразка; F5 посеред розстановки — місце ціле (grace), відлік іде далі.
8. Третє з'єднання без місця бачить обидва поля, підписані ніками, без жодного корабля, і «Дивлюсь збоку».
9. Вікно 380 px: поля лягають одне під одним, клітинка 26×26, горизонтального скролу нема.

## Оновлення 24.09.2026 — до чотирьох капітанів

За всю історію проду в морський бій зіграли **один** раз. Чому, на наш погляд: стіл був рівно на двох
(а друзі сидять утрьох-учетверох), партія на класичному полі довга, і після кожного пострілу поле
відповідало із затримкою до секунди — гра здавалась мляво-«зависаючою». Що змінено:

- **2–4 гравці, `StartMode.ByHost`.** Удвох — та сама класика. Утрьох і вчотирьох — кожен проти кожного:
  у свій хід стріляєш по будь-якому живому чужому полю (`shoot {cell, at}`; без `at` постріл приймається,
  лише коли ціль одна — так старий клієнт і тести на двох працюють як були). Влучив — стріляєш ще (по
  будь-кому), промах — хід наступному живому за колом місць. Чий флот на дні — той вибуває й дивиться
  далі (своє поле з кораблями він і далі бачить, чужих — ні). Останній на плаву виграв.
- **Місця й кольори:** синій ●, червоний ▲, зелений ■, жовтий ◆ — колір плюс форма (для дальтоніків).
  Чіпи в голові картки мають власні класи `bsc0..3` у `battleship.css`, бо x/o/c/d каркаса давали
  «синьому» жовтий колір, а «червоному» — зелений.
- **Вихід посеред партії** (`OnLeave`): удвох — техпоразка, як було. У компанії флот того, хто встав, іде
  на дно, решта грають далі; якщо він ходив — черга переходить; якщо всі інші вже «Готово» в розстановці —
  починається бій. Вибулий (потоплений) глядач може спокійно встати — партії це не чіпає.
- **Годинник ходу 40 с** (`TurnSeconds`): простояв — гармата стріляє сама, навмання, по випадковому живому
  полю. Пропуск ходу був би подарунком тому, хто задумався; чекати без кінця — нечесно щодо решти.
- **Швидке море** — опція `fleet`: `classic` (10×10, десять кораблів, 120 с на розстановку, типова) або
  `quick` (8×8, шість кораблів 3+2+2+1+1+1, 60 с). Правила — `BattleshipSea`; старі методи
  `BattleshipRules` без моря — класика, тож усі старі перевірки на місці. Тексти відмов беруть склад
  флоту з моря («Кораблів має бути рівно шість», «Флот не той: один на три, два на два і три на одну клітинку»).
- **`TickMs` 1000 → 250.** Види після пострілу, як і раніше, летять із тика (каркас не шле їх іграм із
  тиком), але тепер це чверть секунди, а не секунда. Кадр розстановки шлеться лише коли змінилась
  секунда відліку — трафік той самий.
- **Вид**: нові поля `sea`, `players`, `turnUntil`, `turnSeconds`, `placeSeconds`, `feed` (останні 8
  пострілів: хто, по кому, куди, `miss|hit|sunk|out|left`, розмір, `auto`), `boards` тепер для всіх (не лише
  глядача) — масив на 4 місця, `null` для місця, що не грає; у кожному полі — `out` і `reveal` (увесь флот,
  **лише після кінця** партії: наприкінці видно, де ховались чужі кораблі). `result`: `shots/hits/sank` по
  місцях і `places` (переможець, далі — у зворотному порядку потоплення). `enemy` лишився для сумісності.
  Фаза `lobby` — стіл ще не стартував.
- **Клієнт**: сітка полів міряє сама себе (`container-type`): 2/3/4 колонки за шириною картки, на
  телефоні — стовпчиком, і в бою своє поле дрібніше й нижче за чужі. У розстановці малюється лише своє
  поле і список «хто вже готовий»; кнопка «↻ Боком» поруч із «Випадково». Стрічка «хто кого» (у
  компанії), смуга бою з дугою годинника ходу, анімація свіжого пострілу (кільце-бризки, спалах на
  влучанні; `prefers-reduced-motion` вимикає), підсумок партії з місцями, потопленими й влучністю.
- **Виправлено в клієнті**: після влучання (хід лишається тим самим, нового виду не буде) постріл «у
  польоті» знімався з замка вже після малювання, і поля лишались замкненими до наступного виду.
- **Ставки й Ело.** `MaxPlayers` тепер 4, тож ставки зникли (`Rooms.ReadStake` — лише для двох), а Ело
  `Rewards.Elo` і так рахує лише для `MaxPlayers == 2`. Тому `Rated` знято: таблиця гри стала звичайною
  «за перемогами». Старі рядки Ело в базі лишились, просто не показуються.
