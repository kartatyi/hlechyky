# Рулетка (`roulette`, `roulette-solo`) — Дядько Глек за колесом

Класична європейська рулетка: 37 кишеньок 0–36, одне зеро, стандартні ставки й виплати, ставиш черепки з гаманця.
Круп'є — Дядько Глек (`/static/glek.svg`) біля колеса: крутить, кричить «Ставки зроблено!», регоче й згрібає черепки на
зеро, танцює гопак, коли хтось влучив у число, зітхає, коли ніхто не ставить. Колесо розмальоване петриківкою, кулька —
глиняна намистина, фішки — черепки.

Два режими — **дві гри** (два `GameInfo`, один клієнтський модуль), як «Клавоперегони» / «Клавоперегони: тренування» і
«Де це?» / «Де це? Тренування»:
- **За столом** (`roulette`) — спільне колесо для всіх, хто сидить: Глек крутить сам за розкладом (ставки → крутиться →
  виплати → ставки…), підсісти можна будь-коли, глядачі дивляться.
- **Сам на сам** (`roulette-solo`) — своє колесо: ставиш і тиснеш «Крутити», коли хочеш.

Окремі паспорти, бо в каркаса різні дороги для соло (`OpenSolo`, `Private`, `Persistent`, власна таблиця рекордів) і для
столу на кількох; одна гра з опцією так не вміє. У лобі — дві плитки (у «Компанія» й «Соло»), без рядка в `FAMILIES`
`core.js` (як і в Клавоперегонів та «Де це?»).

**Лімітів нема:** ставити можна до всього вільного балансу гаманця, найменша фішка — 1 черепок.

Рішення власника — 08.10.2026. Відкритих питань нема: усе нижче — вирішено.

Перекриття `Game` у спільному столі (`Roulette`):
- `Resumable => true` — `Save()` тримає **увесь** стан (§3.5); `Rooms.Busy()` такий стіл не рахує, деплой його не чекає.
- `Resumed(pause)` — зсуває всі дедлайни (`until` фази, `spin.at/until`, `lastActionAt`) на `pause`.
- `LateJoin(nick) => true` (вільне крісло каркас перевіряє сам); `LateJoinGreeting` → «Сідай ближче! Ставки — до
  «Ставки зроблено!», черепки — з гаманця».
- `OnJoin(seat)` — прочитати баланс у кеш (§3.4), позначити вид брудним; у фазі `idle` нічого не стартує (стартує перша ставка).
- `OnLeave(seat)` — **не техпоразка** й не `Finish`: ставки людини лишаються на столі й розраховуються (§2.8).
- `HoldEmpty => 60 с` — стіл без людей ще хвилину крутить те, що на ньому лежить (найдовше — 25 + 6 + 5 = 36 с), далі
  його прибирає `Housekeeping` (`Finish` не кличеться — `RoomFinished` нема, нагород нема).
- `Frame() => null`, `Tick` ніколи не повертає `Frame: true` — лише види.

Соло (`RouletteSolo`): `Save()`/`Load()`, ключ — типовий `SoloKey` (`roulette-solo:<nick_key>`), одна кімната на ніка.
Обидва класи — нащадки спільного `RouletteGame : Game` (правила, гроші, вид), різниця — лише фази (§2.5, §2.6).

## 2. Правила

### 2.1 Колесо

- Кишеньки 0–36, рівноймовірні. **Червоні:** 1, 3, 5, 7, 9, 12, 14, 16, 18, 19, 21, 23, 25, 27, 30, 32, 34, 36. Решта
  1–36 — чорні, 0 — зелене. Колір на дроті: `"r"`, `"b"`, `"g"`.
- Порядок на колесі (за годинниковою від зеро), для клієнта й `RouletteCore.Wheel`:
  `0, 32, 15, 19, 4, 21, 2, 25, 17, 34, 6, 27, 13, 36, 11, 30, 8, 23, 10, 5, 24, 16, 33, 1, 20, 14, 31, 9, 22, 18, 29, 7, 28, 12, 35, 3, 26`.
- Поле: числа 1–36 у 12 рядах по 3 (`ряд r = (n−1)/3`, 0..11; `колонка c = (n−1)%3`, 0..2: 1-4-7…34 — колонка 1,
  2-5-8…35 — колонка 2, 3-6-9…36 — колонка 3).

### 2.2 Ставки й виплати

| Ставка | Ключ поля (`spot`) | Покриває | Виплата | Повертається при виграші |
|---|---|---|---|---|
| Число | `straight:N`, N 0..36 | 1 | 35:1 | ставка ×36 |
| Спліт | `split:A-B` | 2 | 17:1 | ×18 |
| Вулиця (трійка) | `street:A-B-C` | 3 | 11:1 | ×12 |
| Кут | `corner:A-B-C-D` | 4 | 8:1 | ×9 |
| Лінія (шістка) | `line:A-B-C-D-E-F` | 6 | 5:1 | ×6 |
| Колонка | `column:1` / `column:2` / `column:3` | 12 | 2:1 | ×3 |
| Дюжина | `dozen:1` (1–12) / `dozen:2` (13–24) / `dozen:3` (25–36) | 12 | 2:1 | ×3 |
| Червоне / Чорне | `red` / `black` | 18 | 1:1 | ×2 |
| Парне / Непарне | `even` / `odd` | 18 | 1:1 | ×2 |
| 1–18 / 19–36 | `low` / `high` | 18 | 1:1 | ×2 |

**Зеро.** Випало 0 — програють **усі зовнішні** ставки (колонки, дюжини, червоне/чорне, парне/непарне, 1–18/19–36).
Ні «ла партаж», ні «ан прізон» — класика без поблажок. Внутрішні ставки, що покривають 0 (`straight:0`, `split:0-1`,
`split:0-2`, `split:0-3`, `street:0-1-2`, `street:0-2-3`, `corner:0-1-2-3`), виграють звичайно. Перевага дому — 1/37 ≈ 2,7 %.

**Виграш — «повертається»:** до гаманця йде сума `ставка × (k+1)` по кожній ставці, що зіграла (сама ставка + виграш);
програна ставка лишається в Глека. Чисте `net = повернуто − поставлено` за коло — для таблиці, ачівок і Журналу.

### 2.3 Граматика ключів полів

Числа в ключі — **за зростанням**, через `-`. Сервер приймає числа в будь-якому порядку й зводить до канону; ключ, якого
нема в цьому списку, — «Такої ставки на полі нема».

| Тип | Допустимі множини |
|---|---|
| `straight` | {N}, N ∈ 0..36 |
| `split` | {a, a+1}, a ∈ 1..35, a%3 ≠ 0 (сусіди в ряду); {a, a+3}, a ∈ 1..33 (сусіди в колонці); {0,1}, {0,2}, {0,3} |
| `street` | {a, a+1, a+2}, a ∈ {1, 4, …, 34}; {0,1,2}; {0,2,3} |
| `corner` | {a, a+1, a+3, a+4}, a ∈ 1..32, a%3 ≠ 0; {0,1,2,3} («перші чотири») |
| `line` | {a … a+5}, a ∈ {1, 4, …, 31} |
| `column`, `dozen` | 1, 2, 3 |
| `red`, `black`, `even`, `odd`, `low`, `high` | — |

Людські назви (сервер — для рядків Глека, клієнт — для підказки): «Число 17», «Спліт 17·20», «Вулиця 13·14·15»,
«Кут 17·18·20·21», «Перші чотири», «Лінія 13–18», «Колонка 2», «Дюжина 13–24», «Червоне», «Чорне», «Парне», «Непарне»,
«1–18», «19–36». `RouletteCore` — чиста статика без каркаса: `Wheel`, `ColorOf(n)`, `Read(payload, out spot) → текст відмови | null` (поверх `Canon(key)` і `FromParts(type, numbers, target)` → spot | null),
`Covers(spot) → int[]`, `Pays(spot) → k`, `Return(spot, amount, n) → long`, `MaxReturn(bets) → long`, `MaxPerSpot`, `Label(spot)`.

### 2.4 Ставка гравця

- Ставка на те саме поле — додається до вже поставленого (одна позиція `spot → amount`).
- Порядок дій гравця за коло пам'ятається стеком (для «↶ Відміна»): `bet` — один крок; `repeat` і `double` — один
  складений крок (відміна знімає все, що він поставив).
- Не більше **60 різних полів** на гравця за коло (вид не розростається): «Досить — у тебе вже 60 ставок на полі».
- Суми — `int`; сума на полі й загалом на гравця — `long` під час перевірки, але не більше `int.MaxValue`. Виграш теж
  мусить влізти в `int` (гаманці й леджер — `int`): на одному полі щонайбільше `MaxPerSpot = int.MaxValue / 36`
  (59 652 323) — «Завелика ставка на одне поле»; і найбільше, що рука поверне за будь-якого числа, — не більше
  `int.MaxValue` — «Завеликий можливий виграш — каса стільки за раз не виплатить» (§12).

### 2.5 Фази спільного столу (`roulette`)

| Фаза | Скільки | Що відбувається | Далі |
|---|---|---|---|
| `bets` | `BetMs = 25 000` | ставлять усі, хто сидить | дедлайн: є ставки → закриття (§3.3) → `spin`; нема — «порожнє коло» |
| `spin` | `SpinMs = 6 000` | «Ставки зроблено!», число вже вирішено й лежить у виді, колесо крутиться | дедлайн → розрахунок → `result` |
| `result` | `ResultMs = 5 000` | число, хто скільки виграв, Глек згрібає/платить | дедлайн → ставки зі столу прибираються; хтось сидить → `bets`, нікого → `idle` |
| `idle` | без таймера | Глек дрімає | перша прийнята ставка → `bets` з повним `BetMs` |

- `Start()` (створення столу й «Ще раз» після переривання) → `bets` з дедлайном `now + BetMs`, стіл порожній. Історія
  чисел живе в екземплярі гри й переживає «Ще раз».
- **Порожнє коло** (дедлайн `bets`, ставок нема): лічильник порожніх кіл +1, Глек зітхає (§7.1). Нікого за столом або
  три порожні кола поспіль → `idle`; інакше — нове `bets` з повним `BetMs`. Колесо без ставок **не крутиться**, в історію
  нічого не йде. Будь-яке закрите коло (зі ставками) скидає лічильник у 0.
- Ставка, що прийшла після дедлайну, але раніше за тик, — «Ставки зроблено — чекай наступного кола» (`Act` перевіряє
  `now ≥ until` сам).
- За 5 с до кінця `bets`, якщо ставки є, — один раз за коло підказка Глека «Останні ставки!» (`hurry`).
- `Tick` повертає `View: true` лише на зміну фази, на `hurry` і коли `Act`/`OnJoin`/`OnLeave` позначили вид брудним
  (`Act` у реалтайм-кімнаті видів не шле — так у каркасі; ставка доходить до всіх за ≤ 250 мс). Інакше `TickResult.None`.

### 2.6 Фази соло (`roulette-solo`)

| Фаза | Що | Далі |
|---|---|---|
| `bets` | ставиш скільки хочеш, таймера нема; результат минулого кола (`last`) лишається на виді | `Act spin` → закриття (§3.3) → `spin` |
| `spin` | `SoloSpinMs = 5 000` | дедлайн → розрахунок → `bets` (ставки зі столу прибрано, `last` — це коло) |

- Без дій 120 с у `bets` — Глек дрімає (`doze`), будь-яка дія будить (`idle`).
- `Load` зі станом у фазі `spin` (сайт перезапустився, кімнату прибрали й відкрили знову) — перший же тик розраховує
  це коло (дедлайн у минулому); гроші вже могли піти з відновлення (§3.5) — тоді повтор нічого не платить удруге.

### 2.7 Ніхто не ставить

Спільний стіл — §2.5 (зітхання, після трьох порожніх кіл — дрімота, перша ставка будить). Соло — лише дрімота.

### 2.8 Сісти й встати посеред кола

- Ставити можна лише сидячи. Глядач бачить усе, крім блоку `me`. Сісти посеред партії — `LateJoin` (кнопка модуля
  «🪑 Сісти за стіл», §8.5): з наступної ж дії можна ставити, якщо фаза `bets`/`idle`.
- Встав (чи відпав після grace) посеред будь-якої фази — **ставки лишаються** і зіграють: у `bets` вони закриються разом
  з усіма (списання з гаманця того, хто пішов, — як завжди, по ніку), у `spin` — уже списані й виплатяться. У виді такий
  гравець стоїть із `here: false`, своїм кольором і ставками, поки його ставки на столі; після `result` зникає.
- Ачівки й таблицю отримує лише той, хто в мить розрахунку **сидить** (`Ctx.Award`/`Ctx.Score` ходять за місцем) — як у покері.
- Стіл без людей: `HoldEmpty` 60 с дає докрутити покинуті ставки; нових кіл без людей не починається (після `result` →
  `idle`), за хвилину від останнього виходу каркас прибирає стіл.

### 2.9 Ботів нема

Дім — це Глек. Жодних 🤖 за столом, `SeatBot` не перекрито.

## 3. Черепки

### 3.1 Коли списується

**Одним рухом за коло на гравця, у мить «Ставки зроблено!»** (спільний стіл — дедлайн `bets`; соло — `Act spin`). Поки йде
`bets`, фішки на полі — лише намір: гаманець не чіпається, «↶ Відміна» і «✕ Зняти все» грошей не рухають. Так в історії
гаманця два рядки на коло, а не по рядку на кожен клік фішкою:
- `−125 черепків: Рулетка — ставка` — у мить закриття;
- `Лови +350 черепків: Рулетка — виграш` — коли кулька лягла (кінець `spin`), лише тим, у кого повернення > 0.

Виплата навмисно в кінці `spin`, а не в мить закриття: тост гаманця не має випереджати кульку.

### 3.2 Ключі й причини

| Що | `reason` у леджері | Підпис у гаманці (`Economy.Reason`) | `ref` |
|---|---|---|---|
| ставки за коло | `roulette-bet:<gameId>` | «Рулетка — ставка» | `roulette-bet:{table}:{spin}:{nickKey}` |
| повернення з виграшем | `roulette-win:<gameId>` | «Рулетка — виграш» | `roulette-win:{table}:{spin}:{nickKey}` |
| повернення ставки (лише аварійно, §3.5) | `roulette-back:<gameId>` | «Рулетка — ставку повернуто» | `roulette-back:{table}:{spin}:{nickKey}` |

- `<gameId>` — `roulette` чи `roulette-solo` (для статистики); підпис однаковий для обох — «Рулетка — …» (так попросив
  власник; хвіст коду в підписі не бере участі).
- `{table}` = `{roomId}:{epoch}`; `epoch` — 8 hex, новий у **кожному** `Start()` і **кожному** `Load()`
  (`RandomNumberGenerator`, або `Ctx.Rng`, коли `Ctx.Seeded`). `{spin}` — лічильник закритих кіл у стані гри, росте на
  кожне закриття (і на невдале). Так ключ ніколи не повторюється, навіть коли стан повернувся старішим за леджер
  (знімок «про всяк випадок», недописаний `game_state`): повтор `TrySpend` із тим самим ключем повертає `true` без
  списання — тобто дав би коло задарма, і `epoch` саме від цього.
- `{nickKey}` — `Rooms.NickKey(nick)`, **останній** сегмент ключа (у ніку може бути `:`; ключ порівнюється цілим рядком).
- Коло, що вже в `spin`, пам'ятає свій `table` у собі (`PendingSpin.Table`) — розрахунок іде по ньому, а не по
  поточному `epoch`.

### 3.3 Каса — `RouletteBook` (сервіс на сервер, `Impl/RouletteBook.cs`)

Синглтон + `BackgroundService`, реєструється одним рядком у `GamesSetup` (`Impl.RouletteSetup.AddRoulette(services)`), гра
бере його в `Configure` через `Ctx.Services.GetService<RouletteBook>()`. Нема сервісу — каса зачинена: вид `closed: true`,
кожна ставка — «Каса зачинена — спробуй трохи згодом».

```csharp
public sealed record SpinPay(string Nick, int Stake, int Return);          // Return — Σ ставка×(k+1) по ставках, що зіграли; 0 — програв
public sealed record PendingSpin(string Table, int Spin, string GameId, int Number, DateTimeOffset At, IReadOnlyList<SpinPay> Pays);

public sealed class RouletteBook : BackgroundService
{
    public const string StoreKey = "roulette:pending";      // IGameStore: JSON-словник "{table}:{spin}" → PendingSpin
    public RouletteBook(IStakes stakes, IGameStore store, IClock? clock = null,
        ILogger<RouletteBook>? log = null, Action<Action>? defer = null);   // defer: типово пул потоків; тести — a => a()
    public int Balance(string nick);                         // IStakes.Balance; виняток → 0
    public bool Open(PendingSpin spin);                       // СИНХРОННО записати коло в сховище; false — не записалось
    public bool Take(string nick, int amount, string reason, string refKey);   // СИНХРОННО IStakes.TrySpend; виняток → false
    public void Drop(string table, int spin);                 // прибрати запис (ніхто не заплатив) — синхронно
    public void Settle(PendingSpin spin);                     // ВІДКЛАДЕНО (defer): виплати + прибрати запис
    public int Recover(DateTimeOffset olderThan);             // розрахувати записи з At < olderThan; скільки розраховано
}
```

`Settle(spin)` (і `Recover` — той самий код для кожного запису):
1. `IStakes.Moves("roulette-bet:{table}:{spin}:")` — хто справді заплатив за це коло: рядок із `ref == префікс + nickKey`.
   `null` (економіки нема) — лог і нікому нічого (без економіки ніхто й не платив).
2. Кожному `SpinPay` з `Return > 0`, чий рядок є і `−delta == Stake`, — `IStakes.Grant(nick, Return, "roulette-win:<gameId>",
   "roulette-win:{table}:{spin}:{nickKey}")`. Рядок є, але сума не та (не мало б бути) — лог і `roulette-back` на `|delta|` (для будь-кого з рядком, і для того, хто
   програв: запис зіпсовано — повертаємо списане). `Grant` кинув виняток — запис лишається, підмітання спробує ще (ключі
   не дадуть заплатити двічі).
3. Прибрати запис зі словника й переписати `StoreKey`.

Усе ідемпотентно за `ref`: гра, відновлення на старті й нічне підмітання можуть розрахувати те саме коло — гроші підуть раз.
Запис і читання словника — під власним замком каси.

**Закриття кола (спільний стіл на дедлайні `bets`; соло — у `Act spin`), рівно в такому порядку, під замком кімнати:**
1. Гравці зі ставками > 0 (зокрема ті, хто вже встав) у порядку першої ставки; `stake` — сума їхніх ставок.
2. `spin = ++spinNo`; `n = Draw()` (§4).
3. `Pays` — для кожного `(nick, stake, Return(bets, n))`.
4. `book.Open(new PendingSpin(table, spin, Info.Id, n, now, pays))`. `false` → коло не крутимо: ставки лишаються на
   столі; спільний стіл — нове `bets` з повним `BetMs` і рядок Глека «Каса заїла — це коло не крутимо»; соло —
   `GameError` «Каса зачинена — спробуй трохи згодом».
5. Кожному: `wallet0 = book.Balance(nick)` (для «Ва-банку»), `book.Take(nick, stake, "roulette-bet:<gameId>", ref)`.
   Не списалось (гаманець спорожнів деінде — Лавка, соло-рулетка поруч):
   - спільний стіл — ставки цього ніка знято з кола, `me.note` = «Черепків не стало — твої ставки ({stake}) знято»;
   - соло — `book.Drop(...)`, ставки лишаються на полі, `GameError` «Бракує черепків: у гаманці {wallet}, а на столі {stake}».
6. Не заплатив ніхто (спільний стіл) — `book.Drop`, Глек «Черепків ні в кого не стало — не кручу», нове `bets`.
7. Фаза `spin`: `spin = { no, n, at: now, until: now + SpinMs }`, Глек `call`.

**Розрахунок (тик, `now ≥ spin.until`):** `book.Settle(pending)` → обчислити `last` (§6) з тих, хто заплатив, історію,
`lastBets` (для «Повторити»), серії, ачівки, таблицю, Журнал, рядок Глека (§7) → `result` (спільний) / `bets` (соло).

Запис у сховище (`Open`) і списання (`Take`) — синхронно під замком кімнати, як `BuyIn` покеру: від них залежить, чи
крутиться коло. Виплати (`Settle`) — поза замком (`defer`). Читання балансу — під замком (короткий SELECT).

### 3.4 Перевірка балансу (лімітів нема)

- `me.wallet` — кеш гаманця в стані гри: читається `book.Balance` на кожен `Act` гравця, на `OnJoin` і на початку кожного
  `bets` для всіх, хто сидить (≤ 8 SELECT на коло); між читаннями — мінус списане при закритті, плюс повернене при
  розрахунку. Це підказка; правда — гаманець у шапці сайту.
- `free = wallet − onTable(мої ставки цього кола)`. Нова ставка (і `repeat`, і `double`) приймається, лише якщо її сума
  ≤ `free` (`wallet` — щойно прочитаний у цьому ж `Act`). Інших меж нема: 1 черепок — найменша фішка, весь гаманець —
  найбільша ставка. Єдина межа — арифметика виграшу (§2.4): вона не правило гри, а щоб 35:1 не обрізало.
- Остаточна перевірка — `TrySpend` при закритті (§3.3, крок 5).

### 3.5 Перезапуск і деплой — рівно один розрахунок

| Що сталося | Що з колом у фазі `bets` (фішки ще не списані) | Що з колом у фазі `spin` (списано, не виплачено) |
|---|---|---|
| Деплой із заморозкою (`start.ps1 restart`, `deploy.ps1`) | `Save()` → `Load()` у новому процесі: ставки на місці, дедлайн зсунуто на паузу (`Resumed`) | `Save()` тримає `PendingSpin`; у новому процесі колесо докручується й `Settle` платить. Запис у касі теж є, але `Recover` на старті й підмітання не чіпають кола, яке тримає живий стіл (`RouletteBook.HeldBy`) — гроші приходять, коли лягла кулька. Якщо касу вже виплачено (підмітання старого процесу за довгої заморозки), `Load` доводить коло мовчки (§12) |
| Процес упав (знімок «про всяк випадок» без стану) | стіл перервано (`⚡ Партію перервав перезапуск сайту`), «Ще раз» — новий `Start()` з новим `epoch`. Фішки не списувались — нічого не загублено | `RouletteBook.Recover` на старті розраховує запис **за вже вирішеним числом** (а не повертає ставки): хто заплатив і виграв — отримує, хто програв — ні. Рівно раз, за `ref` |
| Усі встали, стіл прибрано, а коло ще в `spin` | — (у `bets` ставки ще не списані; `HoldEmpty` дає їм дограти) | `HoldEmpty` 60 с дає докрутити; якщо стіл зник раніше — підмітання каси (нижче) |
| Соло: перезапуск / прибрали кімнату посеред `spin` | стан у `game_state` після кожного `Act` | `Recover` на старті / підмітання платить; `Load` при наступному відкритті бачить, що каса запису вже не тримає, і доводить коло **мовчки** — без Журналу, таблиці, ачівок і репліки Глека (§12). Каса ще тримає — кулька лягає в тику, як звичайно |
| Запис кола не ліг у сховище | коло не крутиться, нічого не списано (§3.3, крок 4) | — |

- `RouletteBook.ExecuteAsync`: на старті — `RecoverAtStart()` = `Recover(мить народження каси)` (лише записи старого
  процесу; коло, яке відновлений стіл уже відкрив у цьому, — не чіпаємо), далі раз на 60 с — `Recover(now − 2 хв)` (коло
  живе ≤ 6 с плюс ≤ 60 с заморозки; старіше — сирота, чий стіл зник). Обидва пропускають записи, які тримає живий стіл.
- Вікно, якого не закрито: процес упав між `Open` і першим `Take` — запис є, списання нема → `Recover` нікому не платить
  (перевірка за леджером, §3.3). Між `Take` і `Open` вікна нема — `Open` іде першим.
- `epoch` (§3.2) гарантує, що коло зі старого стану ніколи не перепише ключ уже списаного.
- `Save()` спільного столу (JSON, camelCase) — **увесь** стан: `phase`, `until`, `spinNo`, `epoch` (лише для довідки —
  `Load` бере новий), `bets` (нік, колір, поля, стек відміни, чи сидить), `pending` (`PendingSpin` + список тих, кому
  `Take` удався), `spin` (no, n, at, until), `history`, `last`, `lastBets` по ніку, серії «червоне», `emptyRounds`,
  `hurried`, `glek` (mood, say, seq), `journalAt`, `lastActionAt`, `wallet`-кеш. Соло — те саме.

### 3.6 Нагороди каркаса й таблиця

- Звичайних нагород за партію нема: спільний стіл не кличе `Finish`, поки за ним хтось сидить (лише `HoldEmpty` →
  прибирання; `RoomFinished` не піднімається). «Партія зламалась» (виняток у тику) — єдиний `Finish` з людьми; це

- Таблиця — «найбільший виграш за коло» (`net`): після розрахунку `Ctx.Score(seat, net)` кожному, хто **сидить** і має

  сам `Solo`. Дві окремі таблиці.

## 4. Чесне колесо

- Число вирішує сервер, **у мить закриття** (§3.3, крок 2), рівномірно з 0..36:
  `Draw() => Rig?.Invoke() ?? (Ctx.Seeded ? Ctx.Rng.Next(37) : RandomNumberGenerator.GetInt32(37))`.
- `Ctx.Seeded` — лише в `RoomHarness`/тестах (як у покері); на проді — криптографічний генератор, сід кімнати не допомагає.
- `public Func<int>? Rig { get; set; }` — шов **лише для тестів** («випаде 17»); результат поза 0..36 — `GameError`.
- До закриття числа нема ніде: ні в стані, ні у виді. Після закриття воно у виді (`spin.n`) — клієнт крутить до нього;
  ставки вже не приймаються, тож знання наперед нічого не дає.
- Тест рівномірності: 37 000 тиражів через `Draw()` без `Rig` (`Seeded`) — кожна кишенька 800..1200 разів.

## 5. Дії (`ctx.act(action, payload)`)

| action | payload | Коли | Що робить |
|---|---|---|---|
| `bet` | `{ "spot": "split:17-20", "amount": 25 }` **(так шле клієнт)** або `{ "type": "split", "numbers": [17, 20], "amount": 25 }` / `{ "type": "dozen", "target": 2, "amount": 5 }` / `{ "type": "red", "amount": 5 }` | `bets`, `idle` (спільний: `idle` → `bets`) | додати фішку на поле |
| `undo` | — | `bets`, `idle` | зняти останній крок (ставку чи весь `repeat`/`double`) |
| `clear` | — | `bets`, `idle` | зняти всі мої ставки кола |
| `repeat` | — | `bets`, `idle` (спільний: `idle` → `bets`) | поставити ще раз мої ставки з останнього кола, де я платив (`lastBets`), поверх поточних |
| `double` | — | `bets`, `idle` | подвоїти всі мої поточні ставки (по кожному полю + стільки ж) |
| `spin` | `{}` або `{ "again": true }` | лише соло, `bets` | закрити коло й крутити; `again` і порожній стіл — спершу `repeat`, тоді крутити (одна дія) |

Форма `{type, numbers|target}` — для агентів MCP і власника; сервер зводить її до того самого `spot`. `type` —
`straight|split|street|corner|line|column|dozen|red|black|even|odd|low|high`; `numbers` — для внутрішніх, `target` (1..3) —
для `column`/`dozen`; і `spot`, і `type` разом — береться `spot`.

**Порядок перевірок і тексти** (`GameError`, тост лише тому, хто ходив; стан не міняється):
1. Каси нема (§3.3) → «Каса зачинена — спробуй трохи згодом».
2. Невідома дія → «Тут так не ходять». `spin` у спільному столі → «Тут колесо крутить Глек — за розкладом».
3. Фаза: спільний `spin` або `bets` після дедлайну → «Ставки зроблено — чекай наступного кола»; спільний `result` →
   «Глек рахує виграші — ставки за мить»; соло `spin` → «Колесо крутиться — дочекайся».
4. `bet`: payload не об'єкт / нема ні `spot`, ні відомого `type` / `numbers` не масив цілих → «Не зрозумів ставки»;
   множина не з §2.3 → «Такої ставки на полі нема»; `amount` нема, не ціле або < 1 → «Ставка — ціле число черепків, від 1».
5. Поле нове, а в мене вже 60 полів (і для `repeat`, якщо перевищить) → «Досить — у тебе вже 60 ставок на полі».
6. Гроші (`wallet` щойно прочитано): `bet` — `amount > free` → «Бракує черепків: вільних {free}»; `repeat` —
   «Бракує черепків на повтор: треба {cost}, вільних {free}»; `double` — «Бракує черепків, щоб подвоїти: треба ще {cost},
   вільних {free}».
7. `undo`/`clear` без моїх ставок → «Нема чого знімати»; `repeat` без `lastBets` → «Минулого кола ставок не було — нема чого
   повторювати»; `double` без ставок → «Нема чого подвоювати»; `spin` без ставок (і без `again` з `lastBets`) → «Спершу постав
   хоч один черепок».
8. `spin` соло: каса не записала коло → «Каса зачинена — спробуй трохи згодом»; не списалось → «Бракує черепків: у гаманці
   {wallet}, а на столі {stake}».

Успіх — `ActResult.Done` (без тосту: ставки видно на полі). `lastActionAt = now`, вид брудний. Числа в текстах — як є, без
пробілів між тисячами («вільних 4210»).

ва-банк (виграв чи програв); `sigh` — лише перше порожнє коло серії. Решта — тільки в хмарці над Глеком. Жодних викликів

### 7.4 Гімн переможця на влучне число — свідомо **ні**

Розглянуто хук `AnthemPlayer.PlayFor(roomId, key, nick)` без `RoomFinished` — не робимо:
1. Браузер (`core.js`, `anthemRound`) глушить гімн столу, щойно приходить вид із `status: 'playing'` і іншим `round`, а
   ключ дублю — `стіл:раунд`. Гімн посеред «партії» обірвав би перший же вид (тобто перша ж чужа фішка), а лагодити —
   міняти спільний контракт `anthem` (окремий лічильник) у `core.js`, `Contracts.cs` і `AnthemPlayer`.
2. Число випадає часто (кожна фішка на числі — 1/37, коло — раз на ~36 с), і гімни вісьмох людей гриміли б по колу. Гімн
   на сайті — «один на партію», і заради цього його купують.
3. Прокльон рахує програші партій — з колами він не дружить.

Замість гімну — гопак Глека (`dance`) на картці, рядок у балачці столу й ачівка. `Coop: true` тримає `AnthemPlayer` осторонь
і на рідкісному `Finish`.

## 8. Клієнт (`web/games/roulette.js` + `roulette.css`)

### 8.1 Реєстрація

`HGames.register` двічі (`roulette`, `roulette-solo`) з тим самим набором функцій; `icon` — колесо 16×16 (коло, 8 спиць,
крапка-кулька; `var(--accent)`/`var(--clay)`), `seatNames: (i) => 'місце ' + (i + 1)`, `seatClass` — по колу `x/o/c/d`,
`added: '2026-10-08'`, `pad` (§8.7). Без `ownLeave` — каркасне «Встати» на місці (ставки й так лишаються). Модуль малює
лише тіло картки.

### 8.2 Розкладка

**Широко (картка ≥ 900 px):** зліва колесо (полотно 320 px, `ui.canvas` з DPR) і Глек (`<img src="/static/glek.svg">`
120 px) ліворуч-зверху від колеса з хмаркою `say`; під колесом — смужка історії (20 кружечків, найновіше ліворуч). Справа —
поле класичне горизонтальне: зеро на висоту трьох рядів ліворуч, 12 стовпців × 3 рядки чисел (зверху 3-6-…-36, знизу
1-4-…-34), праворуч три «2:1»; під числами — три дюжини («1–12», «13–24», «25–36»), під ними — шість рівних грошей
(«1–18», «Парне», «♦ Червоне», «♦ Чорне», «Непарне», «19–36»). Нижче — панель фішок і кнопок (§8.4), легенда гравців
(кольорова крапка, нік, на столі, `net` минулого кола) і «Сісти за стіл» для глядача.

**Вузько (картка < 640 px, телефон 375):** зверху рядок «Глек 72 px + колесо 180 px + хмарка» (на екрані ≤ 440 px
хмарка — окремим рядком під Глеком і колесом на всю ширину, §12); під ним історія
(горизонтальна прокрутка лише всередині смужки). Поле **повернуте вертикально**: зеро зверху на всю ширину, далі 12 рядів
по три (1·2·3 … 34·35·36), знизу три «2:1»; ліворуч вузька смуга дюжин (кожна на 4 ряди), праворуч смуга рівних грошей
(кожна на 2 ряди, підписи вертикальні/скорочені: «1–18», «Пар», «♦», «♦», «Непар», «19–36»). Сітка
`grid-template-columns: 34px repeat(3, 1fr) 46px`, ряд 40 px — поле ~560 px заввишки, сторінка гортається вертикально,
горизонтальної прокрутки нема (бічний відступ 16 px — ширина поля ≤ 343 px). Панель фішок і кнопок — `position: sticky;
bottom: 0` (палець завжди біля фішок). Між 640 і 900 — горизонтальне поле під колесом на всю ширину.

### 8.3 Поле: решітка влучань (однакова для обох орієнтацій)

Кожне число має клітинку `(c, r)`, `c = (n−1)%3`, `r = (n−1)/3`. Решітка «напівкроків» `(x, y)`, `x ∈ 0..5`, `y ∈ 0..23`:

| Точка решітки | Ставка |
|---|---|
| `(2c+1, 2r+1)` | `straight:n` |
| `(2c+2, 2r+1)`, c < 2 | `split:n-(n+1)` |
| `(2c+1, 2r+2)`, r < 11 | `split:n-(n+3)` |
| `(2c+2, 2r+2)`, c < 2, r < 11 | `corner:n-(n+1)-(n+3)-(n+4)` |
| `(0, 2r+1)` | `street` ряду r |
| `(0, 2r+2)`, r < 11 | `line` рядів r і r+1 |
| `(2c+1, 0)` | `split:0-(c+1)` |
| `(2, 0)` / `(4, 0)` | `street:0-1-2` / `street:0-2-3` |
| `(0, 0)` | `corner:0-1-2-3` |
| клітинка зеро | `straight:0` |

Горизонтальне поле: вісь решітки `y` (ряди) іде по екрану зліва направо, вісь `x` (колонки) — знизу вгору (зеро
ліворуч, вулиці — під рядком 1-4-…-34, біля дюжин); вертикальне: `x` — зліва направо, `y` — згори вниз (зеро згори,
вулиці — ліворуч, біля смуги дюжин). Влучання в клітинці: дробові `fx, fy ∈ [0,1]`; `< 0,22` чи `> 0,78` по осі — край (сусідня точка решітки), обидві —
кут; край крайньої колонки з боку дюжин (вертикально — лівий, горизонтально — нижній край ряду 1-4-…) — вулиця/лінія; край
першого ряду з боку зеро — ставки з нулем.

**Дотик:** `pointerdown` підсвічує покриті числа й показує мітку («Кут 17·18·20·21 — 8:1»), `pointerup` у тій самій точці —
`bet`; зсув > 12 px чи `pointercancel` — скасування (поле має `touch-action: pan-y`, тож гортати сторінку пальцем можна).
**Миша:** наведення підсвічує й показує мітку, клік ставить. Зовнішні поля — звичайні кнопки.

Фішки на полі: стос-черепок на точці решітки (для країв і кутів — на перетині), з сумою на верхньому черепку; кольоровий
обідок — колір гравця (`--rl-p0…7`); кілька гравців на одному полі — стоси зсунуті на 6 px по колу (до 4, далі «+N»).
Мої — повна насиченість, чужі — 85 %, тих, хто пішов (`here: false`), — 55 %.

### 8.4 Фішки й кнопки

- Номінали: **1, 5, 25, 100, 500** і **«Усе»** (кладе `me.free` цілком). Черепок — неправильний многокутник (`clip-path`),
  кольори поливи: 1 — `--rl-c1` світла глина, 5 — `--rl-c5` теракота, 25 — `--rl-c25` зелена полива, 100 — `--rl-c100`
  кобальт, 500 — `--rl-c500` чорний із золотим краєм. Обрана — піднята й обведена; номінал > `free` — притушений, не
  клікається. Вибір пам'ятається (`localStorage 'roulette_chip'`, у try/catch).
- Кнопки: «↶ Відміна» (`undo`), «✕ Зняти все» (`clear`), «🔁 Повторити · N» (`repeat`, N = `me.repeatCost`), «×2»
  (`double`); соло — велика «🎡 Крутити» (`spin`), а на порожньому полі з `canRepeat` — «🔁 Ще раз і крутити · N»
  (`spin {again:true}`). Доступність — з `me.can*` і фази. Рядок «На столі 130 · вільних 4210».
- Глядачеві з вільним місцем — «🪑 Сісти за стіл» → `HGames.call('JoinRoom', ctx.room.id)`; без місця — «Місць нема — дивись».
- Сидячому, що має ставки на столі, біля «Встати» каркаса нічого не малюємо; у статусі — «Твої ставки зіграють, навіть
  якщо встанеш».

### 8.5 Колесо, кулька, синхрон із сервером

- Колесо: статичне зображення малюється один раз у позаекранне полотно — 37 кишеньок у порядку §2.1 (`--rl-red`,
  `--rl-black`, `--rl-green`), числа, дерев'яний обід (`--rl-wood`) з петриківським орнаментом (кільце «зернят» і
  завитків червоним, жовтим і зеленим), у центрі — глечик-маточина. Кулька — глиняна намистина (радіальний градієнт
  `--clay`, відблиск).
- Обертання — CSS `transform: rotate()` з `transition` (ніякого rAF): колесо за годинниковою, кулька — окремий шар
  проти годинникової. На новий `spin.no` (ще не анімований у цій вкладці): тривалість `T = spin.leftMs` з моменту
  отримання; колесо — `W1 = W0 + 720 + δ` (δ — випадкове 0..360, клієнтське), кулька — `B1 ≡ W1 + i·360/37 (mod 360)`,
  `B1 ≤ B0 − 1800` (≥ 5 обертів), де `i = Wheel.indexOf(n)`; крива `cubic-bezier(.15,.65,.2,1)`. За останні 1,2 с кулька
  «падає» з доріжки на кільце кишеньок (`translateY` внутрішнього елемента з двома відскоками, keyframes).
- `T < 800` мс або фаза вже `result`/після (F5, реконект) — без анімації: колесо й кулька одразу в кінцевому положенні.
- Під час `spin` число на клієнті **не показуємо** (ні в історії, ні на полі): вид його має, але `history`/`last` оновлює
  лише розрахунок; велике «17 чорне» з'являється, коли кулька лягла (`leftMs` 0 або фаза `result`).
- `result`: виграшне число на полі позначене глечиком-маркером; програні стоси їдуть до Глека («згрібання», 600 мс,
  `transform`), на виграшних — стос виплати поруч; виграшна сума кожного в легенді («+1060»). Новий `bets` — поле чисте.

### 8.7 Клавіші й пад

- Клавіші (`onKey`, коди — `e.code`, працює на українській розкладці): стрілки — курсор по решітці §8.3 (крок —
  пів клітинки; з краю поля стрілка в бік зовнішніх полів переводить курсор у ряд зовнішніх, ←→ ходять по 12 зовнішніх,
  стрілка назад повертає на поле); `Enter`/`Space` — поставити обрану фішку під курсор; `Digit1…Digit6` — фішка 1/5/25/
  100/500/«Усе»; `Backspace`/`KeyZ` — відміна; `KeyX` — зняти все; `KeyR` — повторити; `KeyD` — подвоїти; `KeyS` — крутити
  (соло). `Esc` не чіпаємо (каркас). Курсор видно лише після першої стрілки.
- Пад: `pad: { dirs: true, a: 'Enter', x: 'KeyZ', hint: '{dpad} поле · {a} поставити · {x} відміна · {lb}{rb} фішка ·
  {y} крутити/повторити', on(btn) { lb/rb — попередня/наступна фішка; y — соло: крутити, стіл: повторити; true } }`,
  `when: ctx.mine && ctx.playing`.

### 8.8 Звук

WebAudio-синтез, тихо (гучність ≤ 0,08), **типово вимкнено**: кнопка «🔈 звук: вимк» / «🔊 звук: увімк», стан —
`localStorage 'roulette_sound'` (як `dice_sound`), `AudioContext` — лише після жесту. Звуки: клац черепка (поставив фішку;
лише свої), торохтіння кульки під час `spin` (шум крізь смуговий фільтр із клацами, що рідшають), «цок» у кишеньку,
короткий дзвін на свій виграш (три ноти вгору), глухе «бом» на зеро. Глядач і чужі ставки — тиша. Тести й headless-прогони
— без звуку (`--mute-audio`).

### 8.9 Статус (`status(ctx)`)

- спільний `bets`: «Ставки ще 18 с · твоїх на столі 130» (глядач: «Ставки ще 18 с · сядь, щоб ставити»);
- `spin`: «Ставки зроблено — крутиться…»; `result`: «Випало 17 чорне · ти +1060» / «… · ти −50» / «Випало 17 чорне»;
- `idle`: «Глек дрімає — постав, і він прокинеться»; каса зачинена: «Каса зачинена»;
- соло `bets`: «На столі 130 — тисни «Крутити»» / «Став черепки на поле»; соло `spin`: «Крутиться…».

## 11. Свідомі рішення коротко

- Дві гри, а не опція: соло й стіл на кількох у каркасі — різні дороги (`OpenSolo`/`Persistent`/таблиця рекордів).
- Списання — раз за коло в мить «Ставки зроблено!», виплата — коли кулька лягла: чиста історія гаманця, тост не спойлерить.
- Каса поза банком столу: дім платить більше, ніж лежить за столом; переривання розраховується **за вже вирішеним числом**
  із запису в сховищі, а не поверненням (повернення — лише якщо запис зіпсовано).
- `epoch` у ключах леджера: стан, старіший за леджер, не дасть безкоштовного кола.
- Без гімну на влучне число (§7.4); замість нього — гопак Глека, балачка столу, ачівка.
- Без ла партаж і ан прізон; без лімітів, крім 60 полів на гравця за коло (розмір виду, не гроші).

## 12. Уточнення реалізації сервера (08.10.2026)

Дріт (§5, §6) — без змін. Те, чого spec не казав прямо, сервер робить так:
- `me.canUndo/canRepeat/canDouble` — уже з урахуванням фази: поза вікном ставок (спільний `spin`/`result`, `bets` після
  дедлайну, соло `spin`) — `false`. `me.free` у `spin`/`result` = `wallet` (ставки вже списано, двічі не віднімаємо).
- «Каса заїла» й «Черепків ні в кого не стало» — `glek.mood` `sigh` з відповідною реплікою; нове вікно ставок цю репліку
  не перебиває. Перша ставка, що будить `idle`, скидає лічильник порожніх кіл.
- Балачка столу — один рядок на коло з пріоритетом: `dance` > ва-банк > `laugh` (програно ≥ 50).
- `RouletteCore.Label("straight:0")` — «Зеро».
- Соло `spin {again:true}`: якщо повтор поставився, а коло не закрилось (каса, списання), повтор знімається з поля.
- `RouletteBook` має ще `Sweep()` (= `Recover(now − 2 хв)`, його кличе фон раз на 60 с) і `Pending()` (записи каси — для
  тестів і діагностики).
- `Load` у фазі `spin`: каркас зберігає соло лише після `Act` (не після тика, а хука «зберегти після Tick» для
  Persistent-ігор у `Rooms` нема), тож у сховищі коло лишається в `spin` і після того, як кулька лягла. `Load` питає касу
  (`RouletteBook.Holds(table, spin)`): запису нема — коло вже розраховано, і стан доводиться **мовчки** (`Settle(quiet)`:
  `last`, історія, `lastBets`, серії, фаза → соло `bets` / стіл `result` на 5 с від «зараз», `Resumed` цей дедлайн не
  зсуває); каса не платить ще раз, `Ctx.Log`/`Score`/`Award`/`Say` не кличуться, Глек — `idle` без репліки. Запис є чи касу
  не прочитати — як раніше: кулька лягає в тику (гроші однаково підуть раз).
- `Load` наприкінці перечитує гаманці всіх, хто сидить (кеш зі збереження застарів).
- Каса не чіпає кола живого столу: `RouletteBook(held:)` — у сервері `RouletteBook.HeldBy(rooms, table, spin)` (кімната з
  id до першої «:» грає, і її `RouletteGame.Holds` чекає саме це коло; перевірка — під замком кімнати, поза замком каси).
  Відновлення на старті — `RecoverAtStart()` = записи, старші за народження каси (`IClock` у конструкторі). Порядок у
  `Program.cs`: `TablesKeeper.RestoreAtStart()` іде раніше за хостовані сервіси, тож відновлені столи вже «тримають» свої кола.
- Межа арифметики (§2.4): `RouletteCore.Return` — `long` без обрізання; ставки, що дали б виграш понад `int`, не
  приймаються (`bet`, `repeat`, `double`, соло `spin {again}`). Лімітів ставок як правила гри нема.
- Клієнт, телефон: на екрані ≤ 440 px у `L-vert` сцена — `1fr 72px 180px 1fr`, хмарка окремим рядком на всю ширину
  (хвостик угору до Глека, рядок тримає місце й порожнім); ряд фішок не переноситься, а стискається (`flex: 0 1 40px`,
  `aspect-ratio: 1`) — на 320 px фішки ~34 px поруч із годинником, без вилазу.
- `glek.seq`, історія, `lastBets`, серії й `journalAt` переживають `Start()` («Ще раз») — лічильник реплік не йде назад.
